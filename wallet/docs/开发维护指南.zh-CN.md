# Satochip 钱包开发维护指南

这份文档是给以后继续维护这个安卓工程的人看的。

## 1. 当前项目定位

当前工程不是热钱包，而是高安全观察 / 协调器钱包：

- `Arbitrum One` 观察钱包
- 树莓派离线签名请求中转器
- 树莓派签名结果回传后的人工确认广播器
- `DApp / WalletConnect v2` 高安全协调器
- `BTC` 观察账户原型入口

手机里不保存私钥，签名仍由树莓派和卡片完成。

当前代码已经移除了内置 `Hyperliquid` 浏览器和网页注入桥接，不要再按旧的“内置网页钱包”思路维护。

如果以后要把这个钱包扩到更多链、`BTC` 深化或闪电网络，不要直接从当前文件里硬改，先看：

- [../../docs/独立钱包扩展到BTC与闪电网络方案.zh-CN.md](../../docs/独立钱包扩展到BTC与闪电网络方案.zh-CN.md)

## 2. 当前支持范围

### 链与账户

- `Arbitrum One` 观察地址
- `BTC xpub / ypub / zpub` 观察账户原型

### 主要能力

- 观察地址管理
- 资产查询与活动记录
- `EVM` 转账二维码生成
- 树莓派签名结果扫描与广播
- `WalletConnect v2` 会话批准与请求处理
- `personal_sign`
- `eth_signTypedData`
- `eth_signTypedData_v3`
- `eth_signTypedData_v4`
- `eth_signTransaction`
- `BTC PSBT` 冷签请求准备

### 明确不支持

- 手机热签私钥
- 内置 DApp 浏览器
- `wallet_switchEthereumChain`
- `wallet_addEthereumChain`
- `eth_sign`
- `eth_sendRawTransaction`
- 锁屏后继续保留 DApp 会话

## 3. 当前安全模型

维护时要默认守住这些原则，不要为了“好用”悄悄放开：

- 强生物识别是硬门槛
- `ADB / USB 调试`、开发者选项、`Root / Hook`、`test-keys`、调试器连接都拦截
- `WalletConnect` 只接受已验证、`HTTPS`、主机合法的 DApp
- DApp 信任范围按 `主机 + 链 + 地址` 绑定，且 `24 小时` 过期
- App 退后台或锁屏时，主动清空敏感状态并断开会话
- 关键联网主机使用白名单和证书 pinning
- `release` 构建必须使用 `keystore.properties`，禁止回退到 `debug` 签名

如果你打算修改这些规则，请先在提交说明里明确写出“为什么要放宽”，不要隐式改掉。

## 5. 开发环境

建议固定为：

- `JDK 17`
- `Android SDK 34`
- `Android Build Tools 35.0.0`
- Linux / Ubuntu

第一次换机器时，先看：

- [../../docs/安卓构建环境准备.zh-CN.md](../../docs/安卓构建环境准备.zh-CN.md)

项目会优先读取：

1. `local.properties` 里的 `sdk.dir`
2. `ANDROID_SDK_ROOT`
3. `ANDROID_HOME`
4. 默认值 `/home/ak/Android/Sdk`

## 6. 首次配置

### 6.1 Android SDK

```bash
cp local.properties.example local.properties
```

然后把 `local.properties` 里的 `sdk.dir` 改成你机器上的 Android SDK 路径。

### 6.2 发布签名

```bash
cp keystore.properties.example keystore.properties
```

然后把 `keystore.properties` 改成你自己的长期发布 keystore。

注意：

- `release` 构建现在强制要求 `keystore.properties`
- 如果 keystore 变了，手机上的旧包通常不能直接覆盖安装
- 要保持升级链稳定，必须长期保留同一套 keystore

## 7. 构建方式

### 方式 A：标准发布脚本

以后优先用仓库根目录的标准脚本：

```bash
bash scripts/build_wallet_release.sh
```

输出：

```text
dist/satochip-wallet-release.apk
dist/satochip-wallet-release.apk.sha256
dist/satochip-wallet-release.build-info.txt
```

### 方式 B：中文路径或脏环境场景

如果仓库路径里有中文，或者本机 Gradle 环境容易抽风，优先用：

```bash
./scripts/build_local_ascii.sh release
```

脚本会：

1. 复制到纯英文临时路径
2. 自动补 `local.properties`
3. 固定检查 `JDK 17 / SDK 34 / Build Tools 35.0.0`
4. 产出 `dist/` 下的 APK 和 `sha256`

### 方式 C：直接 Gradle

只有在本机环境已经完全稳定时再直接跑：

```bash
./gradlew :app:assembleRelease --console=plain
```

## 9. 每次改完至少回归这些

### 9.1 基本回归

1. 进入 App
2. 强生物识别能正常解锁
3. 首页地址切换正常
4. 资产刷新正常
5. 构造一笔转账请求正常
6. 扫码导入和相册导入正常

### 9.2 DApp 回归

1. `WalletConnect v2` 配对成功
2. 会话批准成功
3. `personal_sign` 正常
4. `eth_signTypedData_v4` 正常
5. 树莓派回签后结果能正常回传给 DApp
6. 锁屏后会话会按高安全策略断开

### 9.3 发布回归

1. 产出 `apk + sha256 + build-info`
2. 新包能覆盖安装旧包
3. 实机启动不被安全拦截误伤
4. `DApp` 签名和扫码广播至少走一遍

## 10. 发布说明

当前推荐的发布认知是：

- GitHub 上保存的是源码
- `dist/` 下保存的是本机构建产物
- 真正要让别人安装时，必须连同 `apk + sha256 + build-info` 一起留档

不要再写“当前 release 使用调试签名”这类旧说法了，当前代码已经不是这样。

## 11. 下次重编不要踩坑

如果你以后只想稳定重编，不想再重新排错，直接按这份顺序走：

1. 切到一个已知稳定提交
2. 固定 `JDK 17`
3. 固定 `SDK 34 / Build Tools 35.0.0`
4. 复用同一套 `keystore.properties`
5. 优先跑 `build_wallet_release.sh` 或 `build_local_ascii.sh`
6. 构建后立即核对 `sha256`
7. 实机验证启动、转账、DApp、扫码回签

更细的步骤请直接看：

- [固定构建与验包流程](固定构建与验包流程.zh-CN.md)
