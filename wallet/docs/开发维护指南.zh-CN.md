# Arbitrum Wallet Android 开发维护指南

这份文档是给以后继续修改 `/home/ak/树莓派/arbitrum-wallet-android` 用的。

## 1. 项目定位

这个 App 的用途不是保存私钥，而是：

- 维护 Arbitrum One 观察地址
- 查询 ETH / USDC / USDC.e / USDT 余额
- 生成给树莓派签名器扫描的请求二维码
- 扫描树莓派签名结果并广播交易
- 处理 `personal_sign` / `signTypedDataV4`
- 扫描外部请求二维码并转成适合树莓派扫描的中转二维码

它本质上是“观察钱包 + 二维码中转器”。

## 2. 目录结构

### 根目录

- `README.md`
  项目概览和快速构建说明
- `docs/开发维护指南.zh-CN.md`
  这份维护文档
- `scripts/build_local_ascii.sh`
  在英文路径下复制工程再构建，适合当前这台机器
- `dist/`
  输出的 APK 和校验文件
- `local.properties.example`
  Android SDK 配置示例

### App 主代码

- `app/src/main/java/io/arbitrum/wallet/MainActivity.kt`
  主界面 Compose UI
- `app/src/main/java/io/arbitrum/wallet/MainViewModel.kt`
  主要状态管理、二维码生成、余额刷新、广播交易
- `app/src/main/java/io/arbitrum/wallet/ContinuousQrScanActivity.kt`
  连续扫码页面，用来扫外部请求码
- `app/src/main/java/io/arbitrum/wallet/QrScanActivity.kt`
  扫树莓派结果二维码
- `app/src/main/java/io/arbitrum/wallet/TpQrCodec.kt`
  TP 请求/响应协议解析
- `app/src/main/java/io/arbitrum/wallet/RelayQrCodec.kt`
  把请求压缩成 `tpr1:index/total.crc.chunk`
- `app/src/main/java/io/arbitrum/wallet/TpRequestBuilder.kt`
  手动构造转账/消息/TypedData 请求
- `app/src/main/java/io/arbitrum/wallet/TpResponseParser.kt`
  解析树莓派返回结果
- `app/src/main/java/io/arbitrum/wallet/ArbitrumRpc.kt`
  链上 RPC 查询和广播
- `app/src/main/java/io/arbitrum/wallet/ArbitrumConfig.kt`
  RPC、链 ID、代币等配置
- `app/src/main/java/io/arbitrum/wallet/WalletConnectBridge.kt`
  WalletConnect 会话桥接
- `app/src/main/java/io/arbitrum/wallet/WalletConnectRequestCodec.kt`
  WalletConnect 请求转成 TP 格式
- `app/src/main/java/io/arbitrum/wallet/QrImageDecoder.kt`
  从图片中识别二维码

## 3. 开发环境

建议使用：

- JDK 17
- Android SDK 34
- Android Build Tools 35.0.0
- Linux / Ubuntu

当前项目会优先读取：

1. `local.properties` 中的 `sdk.dir`
2. 环境变量 `ANDROID_SDK_ROOT`
3. 环境变量 `ANDROID_HOME`
4. 默认值 `/home/ak/Android/Sdk`

## 4. 首次配置

创建 `local.properties`：

```properties
sdk.dir=/home/ak/Android/Sdk
```

如果只是参考，可以先复制示例：

```bash
cd /home/ak/树莓派/arbitrum-wallet-android
cp local.properties.example local.properties
```

## 5. 构建方式

### 方式 A: 直接构建 Debug

```bash
cd /home/ak/树莓派/arbitrum-wallet-android
./gradlew :app:assembleDebug --console=plain
```

输出：

```text
app/build/outputs/apk/debug/app-debug.apk
```

### 方式 B: 当前机器推荐方式

因为当前工程路径里有中文目录，Gradle/Android 某些环境下容易踩坑，所以更推荐：

```bash
cd /home/ak/树莓派/arbitrum-wallet-android
./scripts/build_local_ascii.sh
```

脚本会做这些事：

1. 复制到纯英文目录 `/home/ak/ascii-build-clean/arbitrum-wallet-android`
2. 自动补 `local.properties`
3. 用 JDK 17 构建 Debug APK
4. 把结果复制回 `dist/`

输出：

```text
dist/arbitrum-wallet-debug.apk
dist/arbitrum-wallet-debug.apk.sha256
```

### 方式 C: 构建 Release

```bash
cd /home/ak/树莓派/arbitrum-wallet-android
./gradlew :app:assembleRelease --console=plain
```

输出：

```text
app/build/outputs/apk/release/app-release.apk
```

注意：

- 当前 `release` 使用 debug 签名，适合内部安装测试
- 如果以后要正式分发，需要换成自己的 keystore

## 6. 常见修改入口

### 6.1 改首页 UI 或按钮

优先看：

- `MainActivity.kt`

这里负责：

- 观察钱包首页
- 请求摘要展示
- 中转二维码卡片
- 扫码入口按钮

### 6.2 改请求二维码协议

优先看：

- `RelayQrCodec.kt`
- `TpQrCodec.kt`

其中：

- `RelayQrCodec.kt` 负责 `tpr1:` 中转分片
- `TpQrCodec.kt` 负责 TP 协议解析和响应构造

### 6.3 改二维码扫描能力

优先看：

- `ContinuousQrScanActivity.kt`
- `QrScanActivity.kt`
- `QrImageDecoder.kt`

如果以后要继续优化扫码速度、弱光能力、补光灯、连续对焦，这几处是主入口。

### 6.4 改 RPC / 代币 / 链配置

优先看：

- `ArbitrumConfig.kt`
- `ArbitrumRpc.kt`

这里可以改：

- RPC 地址
- 代币列表
- 链 ID
- 广播交易逻辑

### 6.5 改 WalletConnect

优先看：

- `WalletConnectBridge.kt`
- `WalletConnectRequestCodec.kt`

如果以后要继续增强 DApp 直连、会话管理、请求映射，这两处最关键。

## 7. 典型开发流程

### 场景 1: 改界面

1. 修改 `MainActivity.kt`
2. 执行 `./scripts/build_local_ascii.sh`
3. 安装 `dist/arbitrum-wallet-debug.apk`
4. 真机点一遍主要流程

### 场景 2: 改二维码协议

1. 修改 `RelayQrCodec.kt` / `TpQrCodec.kt`
2. 重新生成请求二维码
3. 用树莓派签名器实扫
4. 再验证返回二维码能否被 App 正确识别

### 场景 3: 改链上交互

1. 修改 `ArbitrumRpc.kt` / `ArbitrumConfig.kt`
2. 先用观察地址刷新余额验证
3. 再测转账广播
4. 最后测失败提示是否正确

## 8. 常见问题

### 8.1 `sdk.dir` 找不到

检查：

- `local.properties`
- `/home/ak/Android/Sdk` 是否存在

### 8.2 中文路径下构建异常

直接改用：

```bash
./scripts/build_local_ascii.sh
```

### 8.3 构建成功但 APK 没在预期位置

Debug 常见位置：

- `app/build/outputs/apk/debug/app-debug.apk`
- `dist/arbitrum-wallet-debug.apk`

Release 常见位置：

- `app/build/outputs/apk/release/app-release.apk`

### 8.4 扫码正常但广播失败

优先检查：

- `ArbitrumRpc.kt`
- RPC 节点是否可用
- 当前链 ID 是否正确
- 请求里 gas / nonce / value / token 参数是否完整

## 10. 以后怎么继续改

如果你以后重新接手，推荐顺序：

1. 先读 `README.md`
2. 再读这份 `docs/开发维护指南.zh-CN.md`
3. 然后按要改的方向进入对应 Kotlin 文件
4. 每改一轮就先打 Debug 包真机验证

这样最不容易把二维码协议、扫码链路和广播链路一起改乱。
