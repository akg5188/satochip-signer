# Satochip 钱包开发维护指南

这份文档是给以后继续维护这个安卓工程的人看的。

## 1. 当前项目定位

当前工程不是热钱包，而是：

- `Arbitrum One` 观察钱包
- 树莓派离线签名中转器
- Hyperliquid 内置浏览器容器
- DApp / WalletConnect 请求二维码处理器

手机里不保存私钥，签名仍由树莓派和卡片完成。

如果以后要把这个钱包扩到 `BTC` 或闪电网络，不要直接从当前文件里硬改，先看：

- [../../docs/独立钱包扩展到BTC与闪电网络方案.zh-CN.md](../../docs/独立钱包扩展到BTC与闪电网络方案.zh-CN.md)

## 2. 当前支持范围

## 4. 开发环境

建议使用：

- JDK 17
- Android SDK 34
- Android Build Tools 35.0.0
- Linux / Ubuntu

第一次换机器时，先看：

- [../../docs/安卓构建环境准备.zh-CN.md](../../docs/安卓构建环境准备.zh-CN.md)

项目会优先读取：

1. `local.properties` 里的 `sdk.dir`
2. `ANDROID_SDK_ROOT`
3. `ANDROID_HOME`
4. 默认值 `/home/ak/Android/Sdk`

## 5. 首次配置

```bash
cp local.properties.example local.properties
```

然后把 `local.properties` 里的路径改成你机器上的实际 Android SDK 路径。

## 6. 构建方式

### 方式 0：仓库标准构建

以后优先用仓库根目录的标准脚本：

```bash
bash scripts/build_wallet_release.sh
```

输出：

```text
dist/satochip-wallet-release.apk
dist/satochip-wallet-release.apk.sha256
```

如果脚本一开始就提示找不到 Android SDK，不要继续直接跑 Gradle。
先把 `local.properties`、`ANDROID_SDK_ROOT` 或 `ANDROID_HOME` 补正确。

### 方式 A：直接构建 release

```bash
./gradlew assembleRelease --console=plain
```

输出：

```text
app/build/outputs/apk/release/app-release.apk
```

### 方式 B：中文路径场景

如果仓库放在中文路径下，建议用：

```bash
./scripts/build_local_ascii.sh release
```

脚本会：

1. 自动找到当前仓库根目录
2. 复制到纯英文构建目录
3. 自动补 `local.properties`
4. 产出 `dist/` 下的 APK 和 `sha256`

Release 输出：

```text
dist/satochip-wallet-release.apk
dist/satochip-wallet-release.apk.sha256
```

Debug 输出：

```text
dist/satochip-wallet-debug.apk
dist/satochip-wallet-debug.apk.sha256
```

## 8. 维护建议

### 每次改完至少做这三件事

1. 重新装 release APK
2. 过一遍首页地址切换
3. 过一遍 Hyperliquid 连接

如果改动开始涉及：

- 新链支持
- 二维码签名协议变更
- `BTC`
- 闪电网络

先暂停，回去看扩展方案文档，不要继续按“当前 Arbitrum 钱包”的思路往里堆功能。

### Hyperliquid 回归重点

每次涉及这些文件时都要重点回归：

- `MainActivity.kt`
- `MainViewModel.kt`

至少确认：

- `Connect -> Satochip Wallet` 有反应
- 页面能拿到地址
- 请求签名后能正常弹出树莓派二维码

## 9. 发布说明

当前 release 构建使用调试签名。

这适合：

- 你自己安装
- GitHub 备份
- 后续继续迭代

要注意：

- 调试签名在不同机器上不一定是同一个 keystore
- 如果以后换机器后继续打包，手机上旧包可能不能直接覆盖安装
- 如果你想保留平滑升级路径，要么长期保留同一套 keystore，要么改成自己的正式 keystore
- `wallet/keystore.properties.example` 已经预留了正式签名配置模板

如果以后要正式分发或上架，再换自己的 keystore 即可。
