# 固定构建与验包流程

这份文档的目标只有一个：让你以后重编 `wallet/` 时尽量少漂移。

## 1. 先固定 4 件事

以后想稳定重编，至少要固定：

1. 源码提交
2. `JDK / SDK / Build Tools`
3. 构建命令
4. 同一套发布 keystore

## 2. 当前不要再硬记某个旧提交号

这份文档不再硬写“稳定提交 = 某个旧 hash”，因为那种写法很快会过时。

以后如果你要追溯仓库里已经保留的那份 APK，先看：

- `dist/satochip-wallet-release.build-info.txt`

里面的：

- `repo_head`
- `artifact_sha256`
- `version_name`

才是当前产物真正对应的基准。

## 3. 当前固定环境

建议固定为：

- `JDK 17`
- `Android SDK 34`
- `Android Build Tools 35.0.0`
- Linux / Ubuntu

环境文档：

- [../../docs/安卓构建环境准备.zh-CN.md](../../docs/安卓构建环境准备.zh-CN.md)

## 4. 当前 release 签名规则

`wallet/` 现在更严格：

- `release` 必须有 `wallet/keystore.properties`
- 没有就直接失败
- 不允许再回退到 `debug` 签名冒充 release

所以你必须长期保存：

- `wallet/keystore.properties`
- 它引用的正式 keystore 文件

## 5. 当前推荐构建命令

### 仓库根目录

```bash
bash scripts/build_wallet_release.sh
```

### `wallet/` 目录纯英文临时路径构建

```bash
cd wallet
./scripts/build_local_ascii.sh release
```

## 6. 构建后的标准检查

至少确认这 3 个文件存在：

- `dist/satochip-wallet-release.apk`
- `dist/satochip-wallet-release.apk.sha256`
- `dist/satochip-wallet-release.build-info.txt`

## 7. 验包步骤

### 校验哈希

```bash
sha256sum dist/satochip-wallet-release.apk
cat dist/satochip-wallet-release.apk.sha256
```

两者必须一致。

### 校验来源

看：

- `dist/satochip-wallet-release.build-info.txt`

确认：

- `artifact_sha256`
- `repo_head`
- `build_script`

## 8. 实机回归清单

不要只看 Gradle 成功。

每次至少验证：

1. 能安装新包
2. 能通过强生物识别
3. 首页 EVM 地址管理正常
4. `Arbitrum` 资产刷新正常
5. EVM 待签名二维码生成正常
6. `BTC` 观察账户导入和同步正常
7. `BTC PSBT` 请求生成正常
8. 树莓派回签扫码正常
9. `WalletConnect v2` 连接正常
10. 锁屏后会话按高安全策略清理

## 9. 最值得记住的一句

以后别靠记忆重编。

每次都按：

- 固定源码
- 固定环境
- 固定命令
- 固定 keystore
- 固定验包步骤

这样结果才最稳。
