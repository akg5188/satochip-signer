# 固定构建与验包流程

这份文档的目标很明确：

- 让你下次重编时尽量得到同样稳定的结果
- 减少“同一套代码换台机器就各种报错”的概率
- 让构建、签名、验包形成固定流程

## 1. 先固定 4 件事

以后想稳定重编，必须同时固定：

1. 固定源码提交
2. 固定 `JDK / Android SDK / Build Tools`
3. 固定构建命令
4. 固定同一套发布 keystore

缺任何一项，结果都可能漂。

## 2. 当前已知稳定基线

截至当前这轮整理，已知稳定提交是：

- `08855b16`

如果你是要重现“这次已经验证可启动、可连接 DApp、可扫码回签”的这版，先切到这个提交再构建。

```bash
git checkout 08855b16
```

如果以后你继续改代码，请在新版本也记录新的稳定提交号，不要只记“差不多是那版”。

## 3. 固定环境

建议固定成下面这组：

- `JDK 17`
- `Android SDK 34`
- `Android Build Tools 35.0.0`
- Linux / Ubuntu

如果你换了 JDK 版本、SDK 平台或 Build Tools，先不要默认结果还能完全一样。

## 4. 固定签名

### 4.1 配置方式

```bash
cd wallet
cp keystore.properties.example keystore.properties
```

然后把 `keystore.properties` 改成你自己的长期发布 keystore。

### 4.2 为什么必须固定同一套 keystore

因为：

- 新包能不能覆盖旧包，取决于签名是不是同一个发布者
- keystore 变了，就算源码完全一样，手机通常也会把它当成不同应用签名来源

### 4.3 当前代码已经做了什么限制

当前 `release` 构建已经禁止回退到 `debug` 签名。

也就是说：

- 没配 `keystore.properties`，`release` 构建会直接失败
- 这是故意的，目的是防止以后又误发一个 debug-signed “release”

## 5. 固定构建命令

### 推荐命令 1：仓库标准构建

在仓库根目录执行：

```bash
bash scripts/build_wallet_release.sh
```

### 推荐命令 2：wallet 目录的纯英文路径构建

如果本机路径复杂、中文目录多，优先用：

```bash
cd wallet
./scripts/build_local_ascii.sh release
```

这个脚本会自动：

- 检查 `JDK 17`
- 检查 `SDK 34`
- 检查 `Build Tools 35.0.0`
- 复制到纯英文临时目录构建
- 产出 `apk + sha256`

### 不优先推荐的命令

```bash
./gradlew :app:assembleRelease --console=plain
```

只有在本机环境长期稳定时，再直接跑这个。

## 6. 构建后的标准检查

每次构建完，至少确认这 3 个文件存在：

```text
wallet/dist/satochip-wallet-release.apk
wallet/dist/satochip-wallet-release.apk.sha256
wallet/dist/satochip-wallet-release.build-info.txt
```

如果你走的是仓库根目录脚本，则产物在根目录 `dist/`。

## 7. 验包

### 7.1 校验 SHA256

```bash
sha256sum wallet/dist/satochip-wallet-release.apk
cat wallet/dist/satochip-wallet-release.apk.sha256
```

这两处的哈希必须一致。

### 7.2 校验是不是同一套签名链

最重要的是：

- 继续使用同一个 `keystore.properties` 指向的 keystore
- 不要临时换发布签名

如果换签名，结果就是：

- 新包可能无法覆盖旧包
- 你会误以为“明明代码没问题，为什么安装有问题”

## 8. 构建完成后的实机回归清单

不要只看 Gradle 成功。

每次至少过下面这些：

1. 安装新包
2. 正常启动并通过强生物识别
3. 首页地址切换正常
4. 资产刷新正常
5. 生成一笔待签名请求正常
6. 树莓派扫码正常
7. 回签扫码正常
8. `WalletConnect v2` 连接正常
9. `personal_sign` 或 `TypedData` 至少签一笔
10. 锁屏后会话按高安全策略断开

## 9. 发布留档建议

以后每次出一个你认为“稳定可用”的版本，至少把下面 4 样留好：

1. APK 文件
2. `sha256` 文件
3. `build-info` 文件
4. 对应源码提交号

推荐格式：

```text
commit=<git commit>
apk=satochip-wallet-release.apk
sha256=<sha256>
signer=<same long-lived keystore>
```

## 10. 你最该记住的一句话

以后不要再靠记忆重编。

每次都按：

- 固定提交
- 固定环境
- 固定命令
- 固定 keystore
- 固定验包步骤

只要这 5 件事不变，结果就会稳定很多。
