# 智能卡 App 使用教程

这份教程对应 `app/` 里的安卓“智能卡”App。

## 1. 它现在是干什么的

当前源码里的真实定位是：

- 扫 `TokenPocket` 请求
- 在手机上显示请求摘要、转账/合约信息、DApp 信息
- 输入智能卡 `PIN`
- 通过 `NFC` 或 `USB-OTG + ACR39U` 直接配合卡签名
- 显示回扫给 `TP` 的结果二维码
- 也能额外生成给树莓派扫描的静态中转二维码

它不是独立钱包，也不存助记词。

## 2. 使用前准备

至少准备好：

- 一张已经初始化过的智能卡
- 卡的 `PIN`
- 支持 `NFC` 的手机，或者 `USB-OTG + ACR39U`
- `TokenPocket`

助记词初始化请在离线电脑里完成，不要在手机上做。

## 3. 主界面现在有哪些东西

当前界面会有这些关键区域：

- `BIP32 路径`
- `卡 PIN`
- `解锁`
- `TP 请求字符串`
- `扫码`
- `解析`
- `贴卡/插卡签名`

解锁成功后，还会显示：

- 当前钱包地址

解析成功后，还会显示：

- 请求摘要
- 转账/合约信息
- DApp 信息
- 树莓派静态中转二维码
- 回扫二维码

## 4. 最常用流程：手机直接配合智能卡签名

1. 在 `TokenPocket` 发起签名或交易
2. 打开这个 App，点 `扫码`
3. 扫 `TP` 请求二维码
4. 输入 `PIN`
5. 点 `解锁`
6. 成功后核对页面里的请求摘要、转账/合约信息、DApp 信息
7. 点 `已核对，允许签名`
8. 点 `贴卡/插卡签名`
9. 用 `NFC` 贴卡，或者插上 `USB-OTG + ACR39U`
10. 签名成功后，让 `TP` 扫回结果二维码

## 5. 另一条流程：把 TP 动态码转成树莓派静态码

当前 App 也支持这条链路：

1. 扫 `TP` 动态码
2. App 解析后生成 `树莓派静态中转二维码`
3. 如果有多张，会自动每 `1` 秒轮播，也能手动切换
4. 让树莓派扫描这组静态码

适合场景：

- `TP` 动态码太快
- 树莓派直接扫不稳

## 6. 常见问题

### 6.1 扫码后提示“请先输入 PIN 并贴卡解锁”

说明你还没有先完成：

- 输入 `PIN`
- `解锁`

### 6.2 贴卡没反应

先确认：

- 手机已开 `NFC`
- 卡片位置对准感应区
- 没有别的 App 抢占 `NFC`

### 6.3 USB 读卡器没反应

先确认：

- `OTG` 正常
- `ACR39U` 已通电
- 已允许 App 访问 USB 设备

### 6.4 为什么页面上会出现树莓派静态中转二维码

因为这个 App 现在同时兼顾两件事：

- 手机直接智能卡签名
- 给树莓派做 `TP` 动态码降速中转

### 6.5 提示 `TypedDataLegacy` 不支持

当前代码不支持旧式数组型 `signTypedDataLegacy`。

优先让 `TP` 或 DApp 改用：

- `signTypedData`
- `signTypedDataV4`
