# TP 签名中转 App 使用教程

这份文档是给日常安装和使用 `tp-qr-relay-android-latest.apk` 的人看的。

## 1. 这个 App 是干什么的

它不是独立钱包。

它的作用是：

- 手机先扫描 `TokenPocket` 的动态签名二维码
- 手机把请求转成适合树莓派扫描的静态中转二维码
- 用户在手机上核对信息后贴卡或插卡签名
- 手机把签名结果再交还给 `TokenPocket`

## 2. 安装后先确认什么

首次打开后，先确认：

- 手机支持 `NFC`，或者你有 `USB-OTG + ACR39U`
- `TokenPocket` 已经能正常发起签名请求
- 你要使用的卡已经完成 `PIN` 和助记词初始化

## 3. 日常签名流程

1. 在 `TokenPocket` 里发起签名或转账。
2. 用这个 App 扫描 `TP` 的动态二维码。
3. 手机会解析请求并展示要给树莓派扫的中转二维码。
4. 在手机上核对请求内容和 DApp 信息。
5. 点击允许签名后贴卡或插卡。
6. App 读卡成功后会显示签名结果二维码。
7. 回到 `TokenPocket` 扫描结果二维码完成后续流程。

## 4. 什么时候用 NFC，什么时候用 USB

- 如果手机本身支持 `NFC`，优先直接贴卡。
- 如果手机没有 `NFC`，就用 `USB-OTG + ACR39U`。

## 5. 常见问题

### 5.1 扫完 TP 二维码后没法继续

先确认：

- 当前请求已经完整解析
- 屏幕上没有错误提示
- 你已经点过“允许签名”之类的确认按钮

### 5.2 贴卡没反应

先确认：

- 手机 `NFC` 已开启
- 卡片位置对准手机感应区
- 当前手机系统没有被别的 App 抢走 `NFC`

### 5.3 USB 读卡器没反应

先确认：

- `OTG` 转接头正常
- 读卡器已被系统识别
- 已允许 App 访问 USB 设备

### 5.4 提示签名地址不一致

说明当前卡里解锁出来的地址和请求期望地址不一致。

这时不要强行继续，先回头核对：

- 当前使用的是哪张卡
- 卡里导入的是不是你要的那套助记词
- `TP` 当前请求对应的地址是不是你预期的地址

### 5.5 结果二维码出来了，但 TP 不认

先确认：

- 手机上的结果二维码是完整显示的
- 屏幕亮度够高
- `TP` 扫的是最终结果二维码，不是中转二维码

## 6. 不要混用

如果你要的是：

- 独立钱包
- 资产页
- 转账
- `Hyperliquid`

那你要装的是独立钱包，不是这个中转 App：

- `dist/satochip-wallet-release.apk`
