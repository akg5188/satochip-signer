# 智能卡 App 开发维护指南

这份文档对应 `app/` 目录当前源码。

## 1. 当前边界

这个工程不是独立钱包。

它当前负责：

- `TokenPocket` 请求二维码解析
- 请求摘要/转账信息/DApp 信息展示
- `NFC` 与 `USB-CCID` 智能卡签名
- 结果二维码回传
- 可选的树莓派静态中转二维码生成

当前不负责：

- 资产页
- 热钱包私钥
- 联网 RPC

## 2. 当前安全边界

按当前 `AndroidManifest.xml`：

- 申请了 `NFC`
- 申请了 `CAMERA`
- 不申请 `INTERNET`

所以它是离线冷签辅助 App，不是联网钱包。

## 3. 当前关键文件

- `app/src/main/java/com/tpsigner/MainActivity.kt`
  主界面、扫码入口、解锁与签名按钮、树莓派静态码展示
- `app/src/main/java/com/tpsigner/MainViewModel.kt`
  请求解析、状态管理、回传字符串、二维码分页
- `app/src/main/java/com/tpsigner/SatochipSigner.kt`
  智能卡解锁、EVM 交易/消息/TypedData 签名
- `app/src/main/java/com/tpsigner/TpQrCodec.kt`
  `TP` 请求与响应编码
- `app/src/main/java/com/tpsigner/RelayQrCodec.kt`
  树莓派静态中转二维码分片
- `app/src/main/java/com/tpsigner/NfcCardManager.kt`
- `app/src/main/java/com/tpsigner/UsbCcidCardManager.kt`

## 4. 构建方式

优先：

```bash
bash scripts/build_tp_relay_apk.sh
```

输出：

- `dist/tp-qr-relay-android-latest.apk`
- `dist/tp-qr-relay-android-latest.apk.sha256`
- `dist/tp-qr-relay-android-latest.build-info.txt`

## 5. 签名规则

当前 `release` 规则：

- 配了 `keystore.properties` 就用正式 keystore
- 没配就回退到 debug 签名

这和 `wallet/` 不一样，别写反。

## 6. 每次改完至少回归什么

1. 扫一个 `TP` 请求
2. 解锁卡并显示地址
3. 走一遍 `NFC` 签名
4. 如果动了读卡器逻辑，再走一遍 `USB-OTG + ACR39U`
5. 检查回扫二维码
6. 如果改了中转逻辑，再检查树莓派静态二维码自动轮播和手动翻页

## 7. 最容易写错的地方

- 不要把它写成“只能给树莓派中转”的工具
- 也不要把它写成“独立钱包”
- 它现在是“手机直接智能卡签名 + 可选树莓派中转”双用途
