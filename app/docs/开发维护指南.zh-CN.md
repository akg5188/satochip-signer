# TP 签名中转 App 开发维护指南

这份文档是给以后继续维护 `app/` 这个安卓工程的人看的。

## 1. 当前定位

这个工程不是独立钱包，而是：

- `TokenPocket` 请求二维码解析器
- 树莓派中转二维码展示器
- 智能卡 `NFC / USB-CCID` 签名客户端
- 签名结果二维码回传器

## 2. 环境要求

- JDK 17
- Android SDK 34
- Android Build Tools 35.0.0
- Linux / Ubuntu 优先

第一次换机器时，先看：

- [../../docs/安卓构建环境准备.zh-CN.md](../../docs/安卓构建环境准备.zh-CN.md)

## 3. 标准构建方式

以后优先在仓库根目录运行：

```bash
bash scripts/build_tp_relay_apk.sh
```

输出：

```text
dist/tp-qr-relay-android-latest.apk
dist/tp-qr-relay-android-latest.apk.sha256
dist/tp-qr-relay-android-latest.build-info.txt
```

如果脚本一开始就提示找不到 Android SDK，不要继续盲试 Gradle。
先按上面的环境文档把 `sdk.dir` 或 `ANDROID_SDK_ROOT` 配好。

## 4. 直接构建方式

如果只是当前机器上快速直编：

```bash
cp local.properties.example local.properties
./gradlew :app:assembleRelease --console=plain
```

输出：

```text
app/build/outputs/apk/release/app-release.apk
```

## 5. 中文路径问题

如果仓库路径、用户目录或 Android SDK 路径里有中文，优先用仓库根目录的标准脚本。

它会把构建放到纯英文临时目录里，减少 Gradle 和 SDK 的路径兼容问题。

## 6. 关键文件

- `app/src/main/java/com/tpsigner/MainActivity.kt`
  主界面、扫码和签名入口 UI
- `app/src/main/java/com/tpsigner/MainViewModel.kt`
  请求解析、签名流程状态、错误提示
- `app/src/main/java/com/tpsigner/SatochipSigner.kt`
  卡片签名执行和结果编码
- `app/src/main/java/com/tpsigner/NfcCardManager.kt`
  NFC 卡访问
- `app/src/main/java/com/tpsigner/UsbCcidCardManager.kt`
  USB-CCID 读卡器访问
- `app/src/main/java/com/tpsigner/TpQrCodec.kt`
  `TokenPocket` 请求解析
- `app/src/main/java/com/tpsigner/RelayQrCodec.kt`
  中转二维码编码

## 7. 每次改完至少回归什么

1. 扫一张 `TP` 请求二维码。
2. 核对请求信息能正常显示。
3. 走一遍 `NFC` 贴卡签名。
4. 如果你改了读卡器逻辑，再走一遍 `USB-OTG + ACR39U`。
5. 确认最终结果二维码能正常显示。

## 8. 当前签名策略

当前 `release` 仍使用调试签名。

这适合：

- 你自己安装
- GitHub 备份
- 后续继续迭代

要注意：

- 换机器后如果调试 keystore 不同，可能无法覆盖安装旧包
- 如果你想保留长期升级路径，建议尽早换成自己的正式 keystore
- 仓库根目录已经提供 `keystore.properties.example` 作为正式签名配置模板
