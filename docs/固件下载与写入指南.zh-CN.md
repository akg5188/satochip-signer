## 1. 当前正式树莓派固件

### 当前推荐树莓派固件

- 如果你现在就在这台电脑上直接刷：
  - `dist/system-update-latest.img.xz`
  - `dist/system-update-latest.img.xz.sha256`
- 如果你是从 GitHub Releases 公开下载：
  - `offline-signer-firmware-20260408-clean`
  - `system-update-latest.img.xz`

当前校验值：

```text
98ce03bc4e0920e0ac555c851384d623fba9c09da9c19df531c575ac5a450023  system-update-latest.img.xz
```

对应正式源码冻结：

- `offline-signer-clean-source-20260408`
- `repo_head = 8a87ae5d1d19d3a7a2809a2b13327afee490364f`

这张现在就是 GitHub 当前公开下载固件，也是本仓库当前正式件。

它怎么对应源码，看：

- [固件与源码对应关系](固件与源码对应关系.zh-CN.md)
- [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)
- [当前测试固件功能与验证范围](当前测试固件功能与验证范围.zh-CN.md)

### 这次正式固件的重点

- 修复 `BlueWallet` 扫回已签名 `BTC PSBT` 的二维码兼容性
- 已签名 `PSBT` 按输入格式回传，不再强制统一成单一路径
- `PSBT / 已签名交易` 二维码恢复优先自动动画输出
- 二维码显示尺寸改成跟随真实画布，不再写死 `240x240`

### Linux 下校验

```bash
cd dist
sha256sum -c system-update-latest.img.xz.sha256
```

如果你是从 GitHub Releases 下载，不要只校验文件，还要一起核对：

- release 名称是不是 `offline-signer-firmware-20260408-clean`
- 资产文件名是不是 `system-update-latest.img.xz`
- `sha256` 是不是：
  `98ce03bc4e0920e0ac555c851384d623fba9c09da9c19df531c575ac5a450023`

### Linux 下烧录 TF 卡

```bash
lsblk
xzcat system-update-latest.img.xz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

把 `/dev/sdX` 换成你的 TF 卡。

### 首次启动后先做什么

1. 进入首页 `离线签名器`
2. 先跑一次 `固件完整性自检`
3. 再试一笔真实扫码流程

注意：

- 自检能发现关键文件缺失、被改、被额外塞文件
- 但如果有人整张卡重刷，仍然要对照 GitHub 上的 `build-info`、`sha256` 和源码 tag
