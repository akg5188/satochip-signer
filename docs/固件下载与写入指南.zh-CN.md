## 1. 当前树莓派固件入口

### 当前仓库保留基线与重建入口

- 当前仓库保留基线 release：
  - `current-head-clean`
  - `dist/system-update-latest.img.xz`
  - `dist/system-update-latest.img.xz.sha256`
- clean `HEAD` 重建入口：
  - `bash scripts/rebuild_official_release.sh firmware-clean`
- 当前工作区测试包：
  - `bash scripts/build_current_firmware.sh`
  - `dist/system-update-worktree-latest.img.xz`
  - `dist/system-update-worktree-latest.img.xz.sha256`
- GitHub 历史公开稳定固件：
  - `offline-signer-firmware-20260410b-clean`
  - `system-update-latest.img.xz`

判断是不是你要的那张，不要再死记旧 sha。
现在统一看这几项：

- `.sha256`
- `.build-info.txt`
- `repo_head`
- `repo_dirty`
- `build_clean_mode`

它怎么对应源码，看：

- [固件与源码对应关系](固件与源码对应关系.zh-CN.md)
- [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)

### 这次正式固件的重点

- 小屏 UI 重新排版，长内容优先改成摇杆上下滚动
- 签名完成后先显示人能看懂的摘要，再决定是否显示二维码
- 写卡后自动回读核验，覆盖指纹、`xpub / zpub`、首个地址和测试签名
- 修复 `查看助记词` 底部滚动留白问题
- 修复 `拍照创建助记词` 后查看原始熵不显示的问题

### Linux 下校验

```bash
cd dist
sha256sum -c system-update-latest.img.xz.sha256
```

如果你刷的是当前工作区测试包，就把文件名换成 `system-update-worktree-latest.img.xz.sha256`。

如果你是从 GitHub Releases 下载，不要只校验文件，还要一起核对：

- 你下的是不是自己要的那一类：
  - `current-head-clean`
  - 或 `offline-signer-firmware-20260410b-clean`
- 资产文件名是不是 `system-update-latest.img.xz`
- `SHA256`、`tag`、`source tag` 统一去看 [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)

### Linux 下烧录 TF 卡

```bash
lsblk
xzcat system-update-latest.img.xz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

把 `/dev/sdX` 换成你的 TF 卡。

如果你刷的是工作区测试包，就把文件名换成 `system-update-worktree-latest.img.xz`。

### 首次启动后先做什么

1. 进入首页 `离线签名器`
2. 先跑一次 `固件自检`
3. 再试一笔真实扫码流程

注意：

- 自检能发现关键文件缺失、被改、被额外塞文件
- 但如果有人整张卡重刷，仍然要对照 GitHub 上的 `build-info`、`sha256` 和源码 tag

- 当前仓库保留基线的 `SHA256` 以仓库里这组文件为准：
