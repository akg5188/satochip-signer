# 固件下载与写入指南

这份文档只讲两类固件：

- `J3R180` 智能卡固件
- 树莓派离线签名器固件

它们完全不是一回事，下载入口和写入方式也不同。

下载前先做这一步：

- [官方程序下载验真与校验](官方程序下载验真与校验.zh-CN.md)

## 1. `J3R180` 智能卡固件

### 文件在哪里

- 本项目固定预编译文件：
  `card-applet/prebuilt/SatoChip-3.0.4.cap`
- 校验文件：
  `card-applet/prebuilt/SHA256SUMS.txt`
- Release：
  `https://github.com/akg5188/satochip-signer/releases/tag/j3r180-card-firmware-20260318`

当前校验值：

```text
ded5a2efbb8a417109a629dd0e0e09711e1ea2c90da4bab79e719cef9f933ec7  SatoChip-3.0.4.cap
```

### 这张 CAP 到底是什么

这张 `CAP` 是：

- `SatochipApplet`

不是：

- `SeedKeeper`

如果你只是想把一张白卡变成当前项目能直接拿来签名的智能卡，才刷这一张。

如果你要刷的是 `SeedKeeper`，不要拿这张 `SatoChip-3.0.4.cap` 去装。
`SeedKeeper` 的官方固定下载、文件名和 `SHA256`，统一看：

- [官方程序下载验真与校验](官方程序下载验真与校验.zh-CN.md)

### 什么时候用

如果你手里是空白 `J3R180` 卡，先写这个 `CAP`。
如果卡里已经同时装好了 `SatochipApplet` 和 `SeedKeeper`，先不要重刷，先跑：

```bash
java -jar gp.jar --list
```

确认现状再决定是否真的需要改动 applet 组合。

### Linux 下最短写卡流程

准备：

- `pcsc-tools`
- `opensc`
- `GlobalPlatformPro`

推荐固定版本：

- `gp.jar`
- `v25.10.20`
- `SHA256 = c88e0c5093032ec4571571f5397b6174e56bf632667950fa5bb716338534b122`

检查读卡器：

```bash
pcsc_scan
```

写入：

```bash
CAP=/path/to/SatoChip-3.0.4.cap
java -jar gp.jar -install "$CAP"
java -jar gp.jar -l
```

写完后再用：

```bash
opensc-tool -s 00A40400085361746F43686970
```

返回 `SW1=0x90, SW2=0x00` 说明 applet 可选中。

后续初始化卡、设 `PIN`、导助记词，看：

- [../backups/satochip-utils/Tails-离线使用教程.zh-CN.md](../backups/satochip-utils/Tails-离线使用教程.zh-CN.md)
- [../card-applet/J3R180刷SatochipApplet与SeedKeeper.zh-CN.md](../card-applet/J3R180刷SatochipApplet与SeedKeeper.zh-CN.md)
- [SeedKeeper 与 SatochipApplet 分工指南](SeedKeeper与SatochipApplet分工指南.zh-CN.md)

## 2. 树莓派离线签名器固件

### 当前推荐树莓派固件

- GitHub release：
  `offline-signer-firmware-20260403-bip85-preview`
- `dist/system-update-bip85-smartcard-test.img.xz`
- `dist/system-update-bip85-smartcard-test.img.xz.sha256`

当前校验值：

```text
c652b4616b4428cea3b4fa6c023f8b8d295380fbb1410d8a6ba853a4fd4bf56b  system-update-bip85-smartcard-test.img.xz
```

这张是现在优先推荐刷的包。

它怎么对应源码，看：

- [固件与源码对应关系](固件与源码对应关系.zh-CN.md)

### 当前 clean 基线

另外还保留：

- `dist/system-update-latest.img.xz`

这张主要是以后做严格重建、对 `sha256` 的 clean 基线，不是现在首先推荐你刷来体验最新功能的包。

### Linux 下校验

以当前推荐包为例：

```bash
cd dist
sha256sum -c system-update-bip85-smartcard-test.img.xz.sha256
```

如果你是从 GitHub Releases 下载，不要只校验文件，还要一起核对：

- release 名称是不是 `offline-signer-firmware-20260403-bip85-preview`
- 资产文件名是不是 `system-update-bip85-smartcard-test.img.xz`
- `sha256` 是不是：
  `c652b4616b4428cea3b4fa6c023f8b8d295380fbb1410d8a6ba853a4fd4bf56b`

### Linux 下烧录 TF 卡

```bash
lsblk
xzcat system-update-bip85-smartcard-test.img.xz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

把 `/dev/sdX` 换成你的 TF 卡。

### 图形工具

也可以直接用：

- Raspberry Pi Imager
- balenaEtcher

思路一样：

1. 选择 `.img.xz`
2. 选择 TF 卡
3. 写入

### 首次启动后先做什么

1. 进入首页 `离线签名器`
2. 先跑一次 `固件完整性自检`
3. 再试一笔真实扫码流程

注意：

- 自检能发现关键文件缺失、被改、被额外塞文件
- 但如果有人整张卡重刷，仍然要对照 GitHub 上的 `build-info`、`sha256` 和源码 tag
