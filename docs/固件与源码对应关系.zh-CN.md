# 固件与源码对应关系

这页只回答一个问题：当前直接下载固件和 clean 基线分别对应哪份源码。

## 1. `system-update-seedkeeper-suite-test.img.xz`

定位：

- 当前这台电脑里最新编出来的测试固件
- 适合：
  现在就想刷机试 `设备登录密码 / SeedKeeper 菜单 / 真随机创建助记词 / 假助记词保存与加载 / 原始熵二维码`
- 不适合：
  当作以后严格逐字节复现的 clean 正式基线

关键值：

- 镜像：
  `dist/system-update-seedkeeper-suite-test.img.xz`
- `sha256`：

  `a832e523aa092bb8e66e9eb38556507661b40202`

## 3. 当前 `main` 是什么

`main` 是滚动开发线，不要把它当成任意历史镜像的精确来源。

想看当前 `main`，直接运行：

```bash
git rev-parse main
```

它包含：

- 修正后的文档
- 让 clean 构建不再回写源码树的可复现性修复

但它不等于任意一张已发布固件的精确源码冻结点。

## 4. 下次该怎么切源码

以后不要再手动记 tag。先跑：

```bash
bash scripts/rebuild_official_release.sh --list
```

### 想追溯当前 clean 正式包

```bash
bash scripts/rebuild_official_release.sh firmware-clean
```

### 想看仓库当前最新文档与源码

```bash
git checkout main
```

## 5. 最重要的原则

- `system-update-seedkeeper-suite-test` 看当前本机测试功能包
- `system-update-seedkeeper-suite-test` 同时也是当前公开下载入口和对应源码 tag
- `system-update-latest` 看当前 clean 正式基线 tag
- 不要拿当前 `main` 直接代替任意一张历史镜像
- 正式重建优先用 `scripts/rebuild_official_release.sh`
- 发布入口和历史版本怎么区分，再看：
  [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)
