# 固件与源码对应关系

这页只回答一个问题：当前仓库里的树莓派镜像，各自对应哪份源码。

## 1. `system-update-latest.img.xz`

定位：

- 历史 clean 稳定备份
- 当前更适合作为“构建与验包基线”

关键值：

- 镜像：
  `dist/system-update-latest.img.xz`
- `sha256`：
  `50d633dc207f6a0c80adeb2b551851cb0610df5c16f21bfde67075303a077982`
- `repo_head`：
  `f4f75ec85a7d4491b5ef16cda725899b8671a13e`
- `repo_dirty=0`
- `build_clean_mode`
  这张历史 clean 基线还没有记录该字段，因为它早于当前 build-info 格式

对应源码基线：

- tag：
  `pi-signer-firmware-20260329`

注意：

- 这张包是已经实机验证通过的功能版
- 它的 `build-info` 仍然是 `repo_dirty=1`、`build_clean_mode=no-clean`
- 当前 `main` 已经补上了可复现构建链路修复，但这张已验证包本身还是历史功能构建件

## 3. 当前 `main` 是什么

`main` 是滚动开发线，不要把它当成任意历史镜像的精确来源。

想看当前 `main`，直接运行：

```bash
git rev-parse main
```

它包含：

- 修正后的文档
- `review-pinless` 的映射说明
- 让 clean 构建不再回写源码树的可复现性修复

但它不等于当前推荐功能包的精确源码冻结点。

## 4. 下次该怎么切源码

### 想追溯当前推荐功能包

```bash
git checkout offline-signer-review-pinless-source-20260401
```

### 想对照 clean 基线

```bash
git checkout pi-signer-firmware-20260329
```

### 想看仓库当前最新文档与源码

```bash
git checkout main
```

## 5. 最重要的原则

- `system-update-latest` 看 clean 基线 tag
- 当前推荐功能包看冻结 tag
- 不要拿当前 `main` 直接代替任意一张历史镜像
- 发布入口和历史版本怎么区分，再看：
  [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)
