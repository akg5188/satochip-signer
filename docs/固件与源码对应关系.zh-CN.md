# 固件与源码对应关系

这页只回答一个问题：当前正式固件对应哪份源码。

## 1. `system-update-latest.img.xz`

定位：

- 当前 clean 正式版
- 现在既适合日常使用，也适合作为“构建与验包基线”

关键值：

- 镜像：
  `dist/system-update-latest.img.xz`
- `sha256`：
  `ba3b136ed80a91e7cb7da32abf707aad616dc9f1cb50c2e83e4a05a1739d6f31`
- `repo_head`：
  `938eb720378b479d6e20bf297beb2738e3d8cbc9`
- `repo_dirty=0`
- `build_clean_mode=clean`
- `runtime_snapshot_tree_sha256`：
  `56393ea0aa3ba4d960ccba57be75b25d064d5ccd8b3b40f6e07b8c250c03354b`

对应源码基线：

- tag：
  `offline-signer-clean-source-20260403`

## 2. 当前 `main` 是什么

`main` 是滚动开发线，不要把它当成任意历史镜像的精确来源。

想看当前 `main`，直接运行：

```bash
git rev-parse main
```

它包含：

- 修正后的文档
- 让 clean 构建不再回写源码树的可复现性修复

但它不等于任意一张已发布固件的精确源码冻结点。

## 3. 下次该怎么切源码

以后不要再手动记 tag。先跑：

```bash
bash scripts/rebuild_official_release.sh --list
```

### 想追溯当前 clean 正式包

```bash
bash scripts/rebuild_official_release.sh firmware-clean
```

### 想看仓库当前最新文档与源码

```bash
git checkout main
```

## 4. 最重要的原则

- `system-update-latest` 看当前 clean 正式 tag
- 不要拿当前 `main` 直接代替任意一张历史镜像
- 正式重建优先用 `scripts/rebuild_official_release.sh`
- 发布入口和历史版本怎么区分，再看：
  [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)
