# 固件与源码对应关系

这页只回答一个问题：当前仓库里的树莓派镜像，各自对应哪份源码。

## 1. `system-update-latest.img.xz`

定位：

- 历史 clean 稳定备份
- 当前更适合作为“构建与验包基线”

关键值：

- 镜像：
  `dist/system-update-latest.img.xz`
- `sha256`：
  `50d633dc207f6a0c80adeb2b551851cb0610df5c16f21bfde67075303a077982`
- `repo_head`：
  `f4f75ec85a7d4491b5ef16cda725899b8671a13e`
- `repo_dirty=0`
- `build_clean_mode`
  这张历史 clean 基线还没有记录该字段，因为它早于当前 build-info 格式

对应源码基线：

- tag：
  `pi-signer-firmware-20260329`

## 2. `system-update-offline-signer-repair7.img.xz`

定位：

- 当前已经实机验证通过的功能版备份
- 日常使用优先参考这张

关键值：

- 镜像：
  `dist/system-update-offline-signer-repair7.img.xz`
- `sha256`：
  `5dc7305c9d003ce948028bfb191921e9de41f7bf6492b037b31f237bc74d244d`
- `repo_head`：
  `d0fd297caa76b5a3ddcc98f1fe4f21cb34e23d1f`
- `repo_dirty=1`
- `build_clean_mode=no-clean`
- `runtime_snapshot_tree_sha256`：
  `e4e3c7b6611ae627efdd2e8f6da6deefb4b62f350a44e1227bfc1c564fb73219`

它精确对应的冻结源码不是当前 `main`，而是：

- branch：
  `repair7-source-freeze`
- tag：
  `offline-signer-repair7-source-20260330`
- commit：
  `4b78de90911e9d407398f8070a4da41b4df11ab0`

这份冻结源码的快照哈希已经和 `repair7` 镜像里的记录对上。

## 3. 当前 `main` 是什么

`main` 是滚动开发线，不要把它当成任意历史镜像的精确来源。

想看当前 `main`，直接运行：

```bash
git rev-parse main
```

它包含：

- 修正后的文档
- `repair7` 的映射说明
- 新旧固件关系说明

但它不等于 `repair7` 的精确源码冻结点。

## 4. 下次该怎么切源码

### 想追溯 `repair7`

```bash
git checkout offline-signer-repair7-source-20260330
```

### 想对照 clean 基线

```bash
git checkout pi-signer-firmware-20260329
```

### 想看仓库当前最新文档与源码

```bash
git checkout main
```

## 5. 最重要的原则

- `system-update-latest` 看 clean 基线 tag
- `repair7` 看冻结 tag
- 不要拿当前 `main` 直接代替任意一张历史镜像
- 发布入口和历史版本怎么区分，再看：
  [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)
