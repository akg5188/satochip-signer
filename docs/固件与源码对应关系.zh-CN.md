# 固件与源码对应关系

这页只回答一件事：哪张树莓派固件，对应哪份源码。

## 1. 当前最重要的两张镜像

- `dist/system-update-latest.img.xz`
  - 这是仓库里原先保留的历史稳定备份
  - 它的对应信息要以 `dist/system-update-latest.build-info.txt` 为准

- `dist/system-update-offline-signer-repair7.img.xz`
  - 这是你已经实机验证通过的备份版
  - 镜像 `sha256`：`5dc7305c9d003ce948028bfb191921e9de41f7bf6492b037b31f237bc74d244d`
  - 构建记录：`dist/system-update-offline-signer-repair7.build-info.txt`

## 2. `repair7` 精确对应哪份源码

`repair7` 不是直接由当前 `main` 编出来的正式 clean release。

它对应的是下面这份精确冻结源码：

- Git 分支：`repair7-source-freeze`
- Git tag：`offline-signer-repair7-source-20260330`
- commit：`4b78de90911e9d407398f8070a4da41b4df11ab0`

这份冻结源码已经和 `repair7` 的运行时快照哈希核对过：

```text
repair7 runtime_snapshot_tree_sha256
e4e3c7b6611ae627efdd2e8f6da6deefb4b62f350a44e1227bfc1c564fb73219

freeze source snapshot_tree_sha256
e4e3c7b6611ae627efdd2e8f6da6deefb4b62f350a44e1227bfc1c564fb73219
```

也就是说：

- 如果你要追溯 `repair7` 到底是哪份源码，认 `offline-signer-repair7-source-20260330`
- 不要直接拿当前 `main` 或 `pi-signer-firmware-20260330` 去代替 `repair7`

## 3. 为什么 `pi-signer-firmware-20260330` 不能代表 `repair7`

因为 `repair7` 当时是从脏工作区打出来的，`build-info` 里写的是：

- `repo_head=d0fd297...`
- `repo_dirty=1`
- `build_clean_mode=no-clean`

后来我们把源码整理、补提交、再推到 GitHub 时，`main` 和 `pi-signer-firmware-20260330` 都已经往前走了。

所以这几个名字代表的是不同含义：

- `offline-signer-repair7-source-20260330`
  - 精确对应 `repair7` 的源码冻结点
- `pi-signer-firmware-20260330`
  - 后续整理过的源码标签
- `main`
  - 仓库最新源码头

## 4. 以后怎么避免再拿错

如果你要用已经验证通过的 `repair7` 固件：

```bash
git checkout offline-signer-repair7-source-20260330
```

如果你只想看仓库当前最新源码：

```bash
git checkout main
```

如果以后再做新的正式固件发布，应该再新增一条新的“镜像 -> build-info -> tag”对应关系，不要复用 `repair7` 这条记录。
