# 固件与源码对应关系

这页只回答一个问题：当前正式固件对应哪份源码。

## 1. `system-update-latest.img.xz`

定位：

- 当前 clean 正式版
- 现在既适合日常使用，也适合作为“构建与验包基线”

关键值：

- 镜像：
  `dist/system-update-latest.img.xz`
- `sha256`：
  `4939345a9134e0aba6a27b6e7b80daed5c16dec207a438eacd346fe2505ac8e1`
- `repo_head`：
  `fb5a376b34918b269abaa97933931b3e10017a2e`
- `repo_dirty=0`
- `build_clean_mode=clean`
- `runtime_snapshot_tree_sha256`：
  `81fc133102edf875409457ab13440b119a6d1434e60748aae6d81646adf728f8`

对应源码基线：

- tag：
  `offline-signer-clean-source-20260401`

## 2. 当前 `main` 是什么

`main` 是滚动开发线，不要把它当成任意历史镜像的精确来源。

想看当前 `main`，直接运行：

```bash
git rev-parse main
```

它包含：

- 修正后的文档
- 让 clean 构建不再回写源码树的可复现性修复

但它不等于任意一张已发布固件的精确源码冻结点。

## 3. 下次该怎么切源码

### 想追溯当前 clean 正式包

```bash
git checkout offline-signer-clean-source-20260401
```

### 想看仓库当前最新文档与源码

```bash
git checkout main
```

## 4. 最重要的原则

- `system-update-latest` 看当前 clean 正式 tag
- 不要拿当前 `main` 直接代替任意一张历史镜像
- 发布入口和历史版本怎么区分，再看：
  [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)
