# 固件与源码对应关系

这页只回答一个问题：当前固件入口到底对应哪份源码。

## 1. 当前默认固件入口

定位：

- 仓库 `dist/` 里当前默认保留的镜像
- 以后不再默认把它绑定到旧的公开 release tag

关键值：

- 镜像：
  `dist/system-update-latest.img.xz`
- 当前 clean 重建入口：
  `bash scripts/rebuild_official_release.sh firmware-clean`
- 当前源码来源：
  `HEAD`
- 当前工作区最新入口：
  `bash scripts/build_current_firmware.sh`
- 当前工作区测试包名：
  `dist/system-update-worktree-latest.img.xz`

也就是说：

- 想要当前 `HEAD` 的 clean 固件，用 `firmware-clean`
- 想要当前工作区最新，包括未提交改动，用 `build_current_firmware.sh`
- `build_current_firmware.sh` 默认不再覆盖 `system-update-latest.*`，而是单独写 `system-update-worktree-latest.*`

## 2. 历史公开固件

如果你要追 GitHub 上公开发布过的 `20260410b` 正式固件，固定对应关系还是保留的：

- 固件 release tag：
  `offline-signer-firmware-20260410b-clean`
- 源码冻结 tag：
  `offline-signer-clean-source-20260410b`
- 源码冻结提交：
  `281d45bfddb9b9150f48c840fafb3aa63aa624fb`
- 历史重建入口：
  `bash scripts/rebuild_official_release.sh firmware-public-20260410b-clean`

这份冻结里包含：

- 小屏 UI 排版收口，长内容优先改成摇杆上下滚动
- 签名完成后先显示摘要，再决定是否显示二维码
- 写卡后自动回读核验，覆盖指纹、`xpub / zpub`、首个地址和测试签名
- `查看助记词` 底部滚动留白修复
- `拍照创建助记词` 原始熵显示修复
- 固件 smoke、桌面模拟、真实 UI 截图和模块导入检查

## 4. 当前 `main` / `HEAD` 是什么

`main` / `HEAD` 是滚动开发线。

现在默认 clean 固件入口已经直接跟随 `HEAD`，所以：

- 想编当前 clean 固件，看 `firmware-clean -> HEAD`
- 想追历史 `20260410b` 公开固件，再看 `offline-signer-clean-source-20260410b`

## 5. 下次该怎么切源码

以后不要再手动记 tag。先跑：

```bash
bash scripts/rebuild_official_release.sh --list
```

### 想重建当前 clean 固件

```bash
bash scripts/rebuild_official_release.sh firmware-clean
```

### 想重建历史 `20260410b` 正式固件

```bash
bash scripts/rebuild_official_release.sh firmware-public-20260410b-clean
```
