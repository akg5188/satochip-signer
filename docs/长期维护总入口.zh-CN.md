## 1. 先记住五个部分

- `card-applet`
  `J3R180` 智能卡固件
- `seedsigner-os`
  树莓派固件源码
- `wallet`
  独立钱包安卓工程
- `app`
  配合 `TokenPocket` 使用的签名中转安卓工程
- `backups/satochip-utils`
  在 `Tails OS` 里设置 `PIN` 和助记词的离线工具备份

## 3. 重新编译时看哪里

### 3.1 独立钱包 `wallet`

首次换机器先看：
[安卓构建环境准备](安卓构建环境准备.zh-CN.md)

```bash
bash scripts/build_wallet_release.sh
```

输出：

```text
dist/satochip-wallet-release.apk
dist/satochip-wallet-release.apk.sha256
```

### 3.2 TP 安卓工程 `app`

首次换机器先看：
[安卓构建环境准备](安卓构建环境准备.zh-CN.md)

```bash
bash scripts/build_tp_relay_apk.sh
```

输出：

```text
dist/tp-qr-relay-android-latest.apk
dist/tp-qr-relay-android-latest.apk.sha256
dist/tp-qr-relay-android-latest.build-info.txt
```

### 3.3 J3R180 卡固件

优先直接用预编译文件：

```text
card-applet/prebuilt/SatoChip-3.0.4.cap
```

如果要自己编译：

```bash
cd card-applet/SatochipApplet
ant
```

### 3.4 树莓派固件

如果只是用现成镜像，不需要编译，直接烧录：

```text
dist/system-update-latest.img.xz
```

如果要重打镜像，优先看：

- [维护说明](维护说明.zh-CN.md)
- [树莓派固件构建与备份](树莓派固件构建与备份.zh-CN.md)
- `scripts/build_pi_firmware_from_snapshot.sh`
- `scripts/run_seedsigner_build.sh`

## 4. 发布和校验时要做什么

### 安卓 APK

- 重新编译
- 生成 `sha256`
- 同步更新仓库里的稳定文件名
- 上传到 GitHub Release
- 如果还在用 debug 签名，换机器后升级安装可能要先卸载旧包

### 卡固件

- 检查 `card-applet/prebuilt/SHA256SUMS.txt`
- 上传 `cap` 和 `SHA256SUMS.txt`

### 树莓派固件

- 检查 `dist/system-update-latest.img.xz.sha256`
- 上传镜像和校验文件

## 5. 最容易踩坑的地方

- `local.properties` 只应该是本地文件，不要长期依赖某一台机器路径
- 换新机器前先看 [安卓构建环境准备](安卓构建环境准备.zh-CN.md)，把 `JDK 17`、`Android SDK 34`、`Build Tools 35.0.0` 补齐
- 安卓构建如果遇到 Google Maven 解析异常，先看 `settings.gradle.kts` 里的镜像源配置
- 需要长期稳定保存的产物，优先保留：
  `latest` 命名文件 + `sha256` + GitHub Release
- `Tails OS` 下卡初始化工具要记得把缩放调成 `100%`

## 6. 最短维护顺序

1. 先看这篇总入口，确认这次要改的是 `card-applet`、`seedsigner-os`、`wallet`、`app` 还是 `backups/satochip-utils`。
2. 改完后先本地重新编译或重新生成产物，再补 `sha256`。
3. 最后同时更新 GitHub Release、仓库里的稳定文件名和相关说明文档。
