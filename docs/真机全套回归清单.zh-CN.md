# 真机全套回归清单

这页不是泛泛建议，而是每次准备把固件、钱包和教程一起推到 `GitHub` 前，应该逐项打勾的最小真机清单。

自动化 smoke 只能证明软件路径大体没断，不能替代：

- 真屏幕
- 真相机
- 真 `Satochip / SeedKeeper`
- 真手机扫码和广播

## 1. 刷机与开机

- 校验 `system-update` 镜像 `sha256`
- 真机烧录 `TF` 卡成功
- 首次开机能进入 `设备登录`
- 能设置 `4-12` 位数字登录密码
- 重启后能再次输入登录密码进入主页
- 首页 4 个入口都可正常进入和退出

## 2. 树莓派二维码与签名

- 手机或上游钱包待签名二维码能被树莓派稳定扫入
- 二维码解析页的金额、地址、矿工费显示正常
- 输入智能卡 `PIN` 后可成功签名
- 已签名结果二维码亮度调节正常
- 自动动画二维码能被手机持续扫回
- 仍需手动翻页的二维码页，左右翻页逻辑正常

## 3. `BlueWallet` 路径

- `BlueWallet` 观察钱包能正常发出 `BTC PSBT`
- 树莓派可识别并完成签名
- `BlueWallet` 可以扫回树莓派返回的已签名结果
- 小额、少输入交易能直接从 `BlueWallet` 页面广播
- 多输入交易如果广播页按钮被长 `tx hex` 挤没，要确认“复制并稍后广播”这条退路可用

## 4. 自家安卓观察钱包路径

- `xpub / ypub / zpub` 导入正常
- 主网 `BTC` 首次同步能快速出现余额
- 最近活动能正常出现
- 能生成 `PSBT` 给树莓派签名
- 能扫回树莓派返回的签名结果
- 能手动确认并广播
- `Arbitrum` 观察地址、资产页、最近活动和 `WalletConnect` 入口没有被 `BTC` 改动带坏

## 5. `TokenPocket` / 智能卡 App 路径

- `app/` 可以扫 `TokenPocket` 动态请求
- `NFC` 或 `USB-OTG + 读卡器` 可完成签名
- 转树莓派静态码的中转入口正常
- 返回 `TokenPocket` 的回扫二维码正常

## 6. `OKX Wallet / Bitget Wallet / MetaMask / Rabby / TokenPocket` Web3 桥接路径

- 树莓派首页 `连接钱包 -> Web3钱包` 可选择 `OKX钱包`、`Bitget钱包`、`MetaMask`、`Rabby`、`TokenPocket`
- 树莓派可选择 `智能卡账户` 或 `已加载助记词账户`
- 树莓派可显示单张静态 Keystone 连接二维码
- `OKX Wallet / Bitget Wallet / MetaMask / Rabby / TokenPocket` 可扫码连接
- `wallet/` 可把高密度 Web3 钱包签名请求二维码转成低密度中转码
- 树莓派可扫中转码并签名
- 树莓派可显示 `eth-signature` 结果二维码给 Web3 钱包扫回

## 7. 助记词与 `BIP85`

- `创建助记词 -> 智能卡创建` 正常
- `创建助记词 -> 扑克牌创建 / 16进制创建 / 骰子创建 / 拍照创建` 正常
- `查看 BIP39 序号`
- `查看原始熵`
- `显示二维码`
- `BIP85` 子助记词查看、验证、导入正常
- 钢板数字恢复和二次还原流程正常

## 8. 智能卡与 `SeedKeeper`

- `Satochip` 地址查看正常
- 导出 `Satochip` 的 `BTC xpub / zpub` 正常
- 写入当前助记词到 `Satochip` 正常
- 写入当前助记词到 `SeedKeeper` 正常
- 保存二次加密助记词到 `SeedKeeper` 正常
- 从 `SeedKeeper` 加载二次加密助记词正常
- 更改 `Satochip PIN`
- 更改 `SeedKeeper PIN`
- 重置 `Satochip`
- 重置 `SeedKeeper`

## 9. 发布前最低记录要求

每次真机回归后，至少要把这些一起留到 `GitHub`：

- 本次测试日期
- 固件 release tag
- 钱包 release tag
- 实测手机型号
- 树莓派硬件型号
- 智能卡类型
- 失败项和已知限制

## 10. 当前最稳的执行顺序

1. 先跑自动化 smoke
2. 再刷真机固件
3. 先过 `BlueWallet` 和自家钱包两条扫码签名主路径
4. 再过 `SeedKeeper / Satochip` 写卡与恢复
5. 再确认 `TokenPocket` 路径
6. 最后确认 `OKX Wallet / Bitget Wallet` Web3 桥接路径

这样最容易尽早发现“修一个地方把别的地方带坏”的回归。
