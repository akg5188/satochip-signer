# 父助记词分仓到多张子卡操作手册

这份手册只讲一件事：

- 用 1 条父助记词
- 派生出多条子助记词
- 分别写进不同智能卡
- 把风险拆开，不再把全部资金压在 1 张卡上

这份手册特别适合下面这种情况：

- 你想继续用智能卡
- 但你又不想把整套父助记词直接写进一张来源不够放心的白卡
- 你希望即使其中 1 张卡出事，也不要影响全部资金

先说最重要的结论：

- 父助记词不要写进便宜白卡
- 白卡只写子助记词
- 白卡只放分仓，不放总仓

如果你还没看过 `BIP85` 基础说明，先看：

## 1. 这套方案到底解决什么问题

它解决的不是“让白卡变成绝对安全”。

它真正解决的是：

- 原来 1 张卡出问题，可能牵连全部资金
- 现在改成 1 张卡只对应 1 个子仓
- 哪怕某张卡真有问题，通常也只影响那一仓

所以它的核心价值是：

- 风险隔离
- 用途隔离
- 金额隔离

## 2. 这套方案不解决什么问题

你一定要先记住这 3 件事：

1. 这不是多签
   每个子仓本身还是单签钱包

2. 父助记词如果泄露，所有子仓一起受影响

3. 白卡如果真有高级后门，仍然不能被这套方案“彻底洗白”

所以这套方案的定位不是：

- 白卡从此绝对安全

而是：

- 白卡就算出事，也尽量只炸一个子仓

## 3. 最推荐的仓位结构

对大多数人，最简单也最稳的是 4 仓：

- `A = 日常卡`
- `B = 备用卡`
- `C = 测试卡`
- `D = 实验卡`

对应建议：

- `日常卡`
  平时要花的小额资金
- `备用卡`
  中等金额，平时少动
- `测试卡`
  新固件、新钱包、新流程先拿它试
- `实验卡`
  专门给高风险玩法、白卡折腾、脚本验证用

如果你手里卡不够，至少也建议先分成 3 仓：

- `日常卡`
- `备用卡`
- `测试卡`

## 4. 父助记词和子卡分别怎么放

### 父助记词

父助记词是总钥匙，规则只有一条：

- 不写进便宜白卡

更稳的做法是：

- 只保留在你最信任的离线备份里
- 可以另外考虑官方 genuine 卡、金属备份、或你自己认可的长期冷备方式

### 子卡

每张白卡只做一件事：

- 保存 1 条子助记词

不要在一张白卡上同时承担：

- 全部资金
- 所有用途
- 测试和正式混用

## 5. 操作前先准备好什么

开始前请先准备：

1. 1 条你已经确认可靠的父助记词
2. 你打算使用的子仓数量
3. 每个子仓的用途
4. 每张卡对应的标签
5. 一张离线记录纸，用来记：
   - 父助记词是谁
   - 每个子仓的 `index`
   - 每张卡的用途

## 6. 建议直接这样命名

卡片标签不要写得太露骨，不要直接写总金额，也不要写“主仓全部资金”。

推荐这样写：

- `日常卡`
- `备用卡`
- `测试卡`
- `实验卡`

你还可以再配一张离线对照纸，只写：

```text
父助记词标签：总种子-主备份
A：日常卡
B：备用卡
C：测试卡
D：实验卡
```

不要在这张对照纸上写：

- 完整助记词
- PIN
- 全部金额

## 7. 每张卡建议放多少钱

最重要的原则不是固定数字，而是这句：

- 单张白卡只放你能承受损失的金额

你可以给自己定一个规则：

- `日常卡`：日常花销
- `备用卡`：中额备用
- `测试卡`：测试金额
- `实验卡`：全损也能接受

一旦某张卡金额超过你能承受的损失上限，就把它拆到别的仓里。

## 8. 树莓派里实际怎么做

推荐按下面顺序来：

1. 在树莓派里加载父助记词
2. 进入：
   `助记词工具 -> 已加载助记词 -> BIP-85 子助记词`
3. 选择词数
4. 输入这个子仓固定使用的 `index`
5. 先查看和核对生成结果
6. 再把这条子助记词写进对应智能卡
7. 写卡完成后做自动回读核验
8. 给这张卡记上用途标签
9. 用极小金额做一次真实签名测试

如果你还不熟 `BIP85` 页面，先看：

- [BIP85子助记词使用教程](BIP85子助记词使用教程.zh-CN.md)

## 9. 最推荐的 index 规划

不要乱用 `index`。

最稳的方式是固定用途，长期不改：

```text
index 0：日常卡
index 1：备用卡
index 2：测试卡
index 3：实验卡
```

或者如果你以后会有更多层级，也可以这样：

```text
index 0：日常卡
index 10：备用卡
index 100：测试卡
index 200：实验卡
```

关键不是哪组数字更高级，而是：

- 你以后自己还能一眼认出来
- 同一个用途不要来回换 index

## 10. 写卡时一定遵守这 4 条

1. 父助记词不要写进便宜白卡
2. 每张卡只写 1 条子助记词
3. 写完马上做回读核验
4. 每张卡写完都先做小额实测

现在固件里已经有：

- 写卡后自动回读核验
- 签名后摘要页
- 当前交易的签名健康检查

所以写完卡以后，至少先确认：

- 指纹一致
- `xpub / zpub` 一致
- 收款地址一致
- 找零地址一致
- 测试签名验签通过

## 11. 每张卡写完后怎么验

不要只看到“写入成功”就结束。

建议每张卡都走这套流程：

1. 写入子助记词
2. 看自动回读核验结果
3. 拔卡重插
4. 再读取一次公开信息
5. 做 1 笔极小金额真实签名测试
6. 确认签名摘要页没有明显异常

如果某张卡出现下面任何一种情况，就不要再放正式资金：

- 回读核验不一致
- 地址对不上
- 测试签名失败
- 当前交易签名检查出现异常

## 12. 父助记词应该怎么备份

父助记词是这整套方案里最重要的东西。

最少要做到：

- 离线保存
- 不进便宜白卡
- 不进联网手机
- 不和所有子卡放同一个位置

更直白地说：

- 子卡可以分开放
- 父助记词必须比子卡更谨慎

因为：

- 子卡丢 1 张，通常只影响 1 仓
- 父助记词丢了或泄露，所有仓一起受影响

## 13. 恢复时应该怎么做

以后真要恢复，不要一上来就乱试。

按这个顺序：

1. 先确认你要恢复的是哪一仓
2. 找到这仓对应的卡或记录
3. 如果卡还在，先优先用卡
4. 如果卡坏了，再用父助记词 + 固定 `index` 重新派生
5. 恢复后先做小额验证
6. 确认没问题后再重新入金

## 14. 这套方案最常见的 6 个错误

### 14.1 把父助记词直接写进白卡

这会让整套分仓意义大幅下降。

### 14.2 子卡用途混着用

比如：

- `测试卡` 先测试
- 后来又放正式资金

这最容易把风险边界弄乱。

### 14.3 没记 `index`

以后恢复时最容易把自己绕晕。

### 14.4 只记卡名，不记父助记词是谁

如果你以后不止 1 条父助记词，会很麻烦。

### 14.5 每张卡都放差不多一样多的钱

这样虽然叫“分仓”，实际没有按风险做分级。

### 14.6 没做小额实测就正式入金

一定先让每张卡自己走通一次真实闭环。

## 15. 给小白的最短执行版本

如果你现在只想照着做，直接用这一版：

1. 保留 1 条父助记词，只做总备份
2. 不把父助记词写进白卡
3. 从父助记词派生：
   - `index 0 = 日常卡`
   - `index 1 = 备用卡`
   - `index 2 = 测试卡`
   - `index 3 = 实验卡`
4. 每张卡只写自己的子助记词
5. 每张卡写完都做自动核验
6. 每张卡先做小额测试
7. 日常转账只用 `日常卡`
8. 新功能一律先用 `测试卡`

## 16. 最后的建议

这套方案很适合你现在这种情况：

- 不想裸保管很多完全独立的助记词
- 又不想把全部信任压在 1 张便宜白卡上

但你还是要记住一句话：

- 这套方案的意义是“限制单卡风险”
- 不是“让不可信白卡自动变可信”
