# 安卓构建环境准备

这份文档只讲当前仓库里的两个安卓工程：

- `app/`
  `TokenPocket` 配套安卓“智能卡”App
- `wallet/`
  安卓高安全观察钱包

## 1. 两个工程共用的基础环境

最低要求：

- `JDK 17`
- `Android SDK Platform 34`
- `Android Build Tools 35.0.0`
- `platform-tools`

先检查：

```bash
java -version
javac -version
```

再检查 SDK：

```bash
ls ~/Android/Sdk
```

至少应有：

- `platforms/android-34`
- `build-tools/35.0.0`
- `platform-tools`

## 2. SDK 没装全怎么办

如果你已经有 `sdkmanager`：

```bash
sdkmanager "platform-tools" "platforms;android-34" "build-tools;35.0.0"
```

如果没有，最省事的办法还是先装 Android Studio，让它把 SDK 下齐。

如果想直接按仓库当前标准把本机 SDK 补到可用状态，也可以运行：

```bash
bash scripts/setup_android_sdk_local.sh
```

它会：

- 安装 `platform-tools`
- 安装 `platforms;android-34`
- 安装 `build-tools;35.0.0`
- 自动写好根目录和 `wallet/` 的 `local.properties`

## 3. 仓库怎么找 SDK

根目录脚本和 `wallet/scripts/build_local_ascii.sh` 的检测顺序大体一致：

1. `local.properties` 里的 `sdk.dir`
2. `ANDROID_SDK_ROOT`
3. `ANDROID_HOME`
4. 常见默认路径，例如 `~/Android/Sdk`

最稳的做法：

### 根目录

```bash
cp local.properties.example local.properties
```

### `wallet/`

```bash
cd wallet
cp local.properties.example local.properties
```

然后把 `sdk.dir` 改成你机器上的真实路径。

## 5. 发布签名一定要分开看

### `app/`

当前 `app/build.gradle.kts` 的逻辑是：

- 配了 `keystore.properties` 就用正式 keystore
- 没配就回退到 `debug` 签名

适合：

- 自己安装测试
- 临时本地备份

不适合：

- 想长期平滑升级却又经常换电脑

### `wallet/`

当前 `wallet/app/build.gradle.kts` 更严格：

- `release` 构建必须有 `wallet/keystore.properties`
- 没有就直接失败
- 不允许再回退到 `debug` 签名冒充 release

所以钱包如果想长期维护，必须保留同一套发布 keystore。

## 6. 推荐的 keystore 准备方式

### 根目录示例

```bash
cp keystore.properties.example keystore.properties
```

### `wallet/` 示例

```bash
cd wallet
cp keystore.properties.example keystore.properties
```

然后按你的正式 keystore 改：

- `storeFile`
- `storePassword`
- `keyAlias`
- `keyPassword`

## 7. 常见坑

- `wallet` 的 release 没 keystore 会直接失败，这是正常保护
- `app` 即使能回退 debug 签名，也不代表适合长期升级
- 换电脑后如果 keystore 变了，旧包通常无法覆盖安装
- 优先用根目录脚本，不要先手动裸跑 Gradle

## 8. 新机器最短恢复步骤

1. 安装 `JDK 17`
2. 安装 `platform-tools`、`platforms;android-34`、`build-tools;35.0.0`
3. 配好根目录与 `wallet/` 的 `local.properties`
4. 恢复自己的 keystore
5. 运行标准脚本构建
