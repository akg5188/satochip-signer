# 安卓构建环境准备

这份文档是给以后换电脑、重装系统，或者多年后忘了安卓环境怎么配时用的。

当前仓库里有两个安卓工程：

- `app/`
  TP 签名中转 APK
- `wallet/`
  独立钱包 APK

它们共用同一套基础环境要求。

## 1. 最少需要什么

- JDK 17
- Android SDK Platform 34
- Android Build Tools 35.0.0
- Android platform-tools

## 2. 先检查机器上有没有

```bash
java -version
javac -version
```

如果 `java` 不是 `17`，或者 `javac` 不存在，先装或切到完整 `JDK 17`。

再检查 Android SDK 常见位置：

```bash
ls ~/Android/Sdk
```

至少要能看到这些目录：

- `platforms/android-34`
- `build-tools/35.0.0`
- `platform-tools`

## 3. 没装 Android SDK 怎么办

可以用 Android Studio，也可以用命令行工具安装。

如果你已经有 `sdkmanager`，执行：

```bash
sdkmanager "platform-tools" "platforms;android-34" "build-tools;35.0.0"
```

如果你没有 `sdkmanager`，最省心的方法是先装 Android Studio，让它把 SDK 下载好，再回到这个仓库继续。

## 4. 仓库怎么知道 SDK 在哪

优先顺序是：

1. 当前工程目录下的 `local.properties`
2. `ANDROID_SDK_ROOT`
3. `ANDROID_HOME`
4. 常见默认路径，比如 `~/Android/Sdk`

最稳的做法是直接建 `local.properties`。

仓库根目录的安卓工程：

```bash
cp local.properties.example local.properties
```

独立钱包工程：

```bash
cd wallet
cp local.properties.example local.properties
```

然后把里面的 `sdk.dir` 改成你机器上的真实路径。

## 5. 标准构建命令

TP 签名中转 APK：

```bash
bash scripts/build_tp_relay_apk.sh
```

独立钱包 APK：

```bash
bash scripts/build_wallet_release.sh
```

这两个脚本都会：

- 自动找 `JAVA_HOME`
- 自动尝试定位 Android SDK
- 在缺 SDK 或缺组件时直接报清楚，不会再等几分钟才给你一串 Gradle 错误

## 6. 正式签名怎么准备

当前两个安卓工程都支持两种模式：

- 没有 `keystore.properties`
  继续使用默认 debug 签名
- 有 `keystore.properties`
  自动切换到你自己的正式 keystore

示例文件：

- 仓库根目录：`keystore.properties.example`
- 独立钱包目录：`wallet/keystore.properties.example`

第一次配置时：

```bash
cp keystore.properties.example keystore.properties
```

或者：

```bash
cd wallet
cp keystore.properties.example keystore.properties
```

再把里面四个字段改成你自己的真实值。

## 7. 为什么推荐早点换正式签名

如果一直用 debug 签名：

- 自己测试是方便的
- 但换电脑后，新的 APK 不一定能覆盖旧包
- 很容易出现“只能先卸载、再重装”的情况

如果你希望以后手机上能平滑升级，最好尽早固定自己的 release keystore。

## 8. 新机器最短恢复步骤

1. 装好 `JDK 17`
2. 装好 Android SDK 的 `platform-tools`、`platforms;android-34`、`build-tools;35.0.0`
3. 配 `local.properties`
4. 如果要保留升级路径，再恢复自己的 `keystore.properties`
5. 运行标准脚本重新构建
