# 树莓派签名器使用教程

这份文档只讲一件事：

- 当前这版树莓派固件到底能配合哪些钱包用
- 每种钱包的实际扫码顺序是什么
- 以后时间久了忘了时，应该先看哪几个文件，避免又刷错包、用错协议或重编出不一样的固件

## 1. 当前这版固件支持什么

当前稳定固件：

- 镜像文件：`dist/system-update-latest.img.xz`
- 校验文件：`dist/system-update-latest.img.xz.sha256`
- 构建记录：`dist/system-update-latest.build-info.txt`

当前已经验证过的使用入口有 3 条：

1. 你自己的安卓观察钱包 `satochip-wallet-release.apk`
2. 外部 `BlueWallet`
3. `TokenPocket` 配套中转安卓 App `tp-qr-relay-android-latest.apk`

不要把这 3 条入口混在一起理解：

- `satochip-wallet-release.apk` 是你自己的安卓观察钱包
- `BlueWallet` 是外部钱包，不在这个仓库里
- `tp-qr-relay-android-latest.apk` 只是给 `TokenPocket` 做二维码中转

## 2. 以后先认这几个固定入口

如果以后你只想快速确认“现在该用哪张固件、对应哪份源码”，先看下面这几个固定入口：

- 稳定固件：`dist/system-update-latest.img.xz`
- 固件校验：`dist/system-update-latest.img.xz.sha256`
- 固件构建记录：`dist/system-update-latest.build-info.txt`
- 本次源码标签：`pi-signer-firmware-20260329`

这次稳定固件对应的关键值是：

```text

50d633dc207f6a0c80adeb2b551851cb0610df5c16f21bfde67075303a077982

build-info 里的源码提交
```

以后如果你要“尽量编出和这版一致的固件”，不要直接拿未来的 `main` 头来编，先切到：



## 3. 树莓派开机后怎么找入口

当前固件默认是 `TP only mode`。

也就是说：

- 开机后默认就会进“扫码签名”入口
- 如果你退回菜单，会看到 `TP 签名器`
- 菜单里常用的是：
  - `扫码签名`
  - `导出 BTC zpub`
  - `导出 BTC xpub`

如果你是要签交易，默认就用：

- `扫码签名`

## 4. 二维码显示时怎么调亮度

树莓派在显示结果二维码时，可以直接调屏幕亮度。

操作方式：

- 按硬件 `上` 键：更亮
- 按硬件 `下` 键：更暗

建议：

- 手机扫得慢时，先把树莓派二维码调亮一点
- 手机不要贴太近，先离开一点对焦，再慢慢靠近
- 尽量正对屏幕，减少反光

## 5. 配合你自己的安卓钱包怎么用

对应安卓包：

- `dist/satochip-wallet-release.apk`

源码目录：

- `wallet/`

详细钱包说明：

- `wallet/docs/使用教程.zh-CN.md`

### 5.1 EVM 转账

流程固定为：

1. 手机上在 `satochip-wallet-release.apk` 里准备转账
2. App 生成待签名二维码
3. 树莓派用 `扫码签名` 扫手机上的二维码
4. 树莓派提示输入智能卡 `PIN`
5. 智能卡完成签名
6. 树莓派显示签名结果二维码
7. 手机扫回签名结果
8. 手机上人工确认后广播

### 5.2 BTC 转账

流程固定为：

1. 先在树莓派导出 `zpub/xpub`
2. 在 `satochip-wallet-release.apk` 里导入观察账户
3. 手机准备 `BTC PSBT`
4. 手机自动轮播给树莓派扫描
5. 树莓派审核 `PSBT`
6. 树莓派签名并回显结果二维码
7. 手机扫回结果
8. 手机上人工确认后广播

如果以后忘了导观察账户怎么走，先记一句：

- 树莓派负责导出 `xpub/zpub` 和离线签名
- 手机只负责看余额、准备请求、扫回结果和广播

## 6. 配合 BlueWallet 怎么用

`BlueWallet` 不在这个仓库里，但当前这版树莓派固件已经兼容它的 `BTC PSBT` 二维码签名流程。

当前支持的重点是：

- `BlueWallet` 发给树莓派的动画 `PSBT`
- `BlueWallet` 常用的 `BBQR`
- 手动切协议时常见的 `URv2`

### 6.1 标准流程

1. 在 `BlueWallet` 里创建 `BTC` 交易
2. 让 `BlueWallet` 显示待签名的动画二维码
3. 树莓派停在 `扫码签名` 页面扫描
4. 树莓派解析完成后输入智能卡 `PIN`
5. 树莓派完成签名并显示回传二维码
6. `BlueWallet` 扫回树莓派二维码
7. 在 `BlueWallet` 里确认并广播

### 6.2 关于协议和二维码

这版固件已经专门兼容了 `BlueWallet` 的这两类返回：

- `BBQR`
- `URv2`

所以平时建议：

- 先直接用 `BlueWallet` 默认动画二维码
- 如果你手动切协议，优先用 `BBQR`
- 需要兼容测试时，也可以切 `URv2`

当前树莓派签名后的返回二维码，不再走那种超高密度单张码，而是改成了低密度动画码，目的是让手机更容易扫。

### 6.3 如果 BlueWallet 扫回仍然偏慢

优先按这个顺序排查：

1. 树莓派二维码界面按 `上` 键提亮
2. 手机别贴太近，先稍远对焦
3. 让手机至少看完整一轮动画
4. 避开屏幕反光

如果是“已经扫回，但广播失败”，优先怀疑交易本身，而不是先怀疑签名器。最常见的是：

- 找零过小
- 手续费策略不合适
- 节点拒绝广播

## 7. 配合 TokenPocket 怎么用

如果你是配合 `TokenPocket` 商业钱包，不要直接让树莓派去扫 `TokenPocket` 的动态二维码。

正确入口是：

1. 手机上打开 `tp-qr-relay-android-latest.apk`
2. 先让这个中转 App 扫 `TokenPocket` 动态二维码
3. 中转 App 再把静态码或低频码展示给树莓派
4. 树莓派扫、输 PIN、签名
5. 手机再扫回结果

也就是说：

- `TokenPocket` 要先经过仓库里的中转 App
- `BlueWallet` 不需要这个中转 App
- 你自己的 `satochip-wallet-release.apk` 也不需要这个中转 App

## 8. 最容易混淆的地方

以后如果只记 4 句，记这 4 句：

1. `system-update-latest.img.xz` 是树莓派稳定固件。
2. `satochip-wallet-release.apk` 是你自己的安卓观察钱包。
3. `BlueWallet` 直接配合树莓派扫 `BTC PSBT`，不走 TP 中转 App。
4. `tp-qr-relay-android-latest.apk` 只给 `TokenPocket` 做扫码中转。

## 9. 以后怎么避免又编出不一样的固件

以后如果你真要重编，而且想尽量复现这次验证通过的版本，固定按下面顺序来：

1. 先切源码标签：
   `git checkout pi-signer-firmware-20260329`
2. 再跑正式构建：
   `bash scripts/build_pi_firmware_from_snapshot.sh`
3. 再跑校验：
   `bash scripts/check_release_artifacts.sh`
4. 最后看：
   `dist/system-update-latest.build-info.txt`

真正要盯的只有两项：

- `repo_head` 必须是你预期的源码提交
- `repo_dirty` 必须是 `0`

只要这两项不对，就不要把那张镜像当正式稳定版。
