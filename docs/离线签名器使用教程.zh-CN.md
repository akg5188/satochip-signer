# 离线签名器使用教程

这份教程完全按当前源码重写，重点只讲现在机器里真实存在的功能。

## 1. 当前首页

树莓派开机后首页标题就是：

- `离线签名器`

首页 4 个入口：

- `扫码签名`
- `助记词工具`
- `固件完整性自检`
- `智能卡工具`

首页左上角没有返回按钮，这是当前代码里的设计。

## 2. `扫码签名` 现在支持什么

### 2.1 自己的安卓观察钱包

适合：

- `wallet/` 生成的 EVM 请求
- `wallet/` 生成的 `BTC PSBT` 请求

流程：

1. 手机显示待签名二维码
2. 树莓派进 `扫码签名`
3. 输入智能卡 `PIN`
4. 树莓派签名
5. 手机扫回并人工确认广播

### 2.2 `BlueWallet`

当前固件已经识别：

- `BBQR`
- `UR`
- 常见 `PSBT` 分片

流程：

1. `BlueWallet` 创建 `BTC` 交易
2. 让它显示待签名 `PSBT`
3. 树莓派扫入
4. 输入智能卡 `PIN`
5. 树莓派回显签名结果
6. `BlueWallet` 扫回并广播

### 2.3 `TokenPocket`

树莓派不直接吃高频 `TP` 动态码。

当前推荐做法：

1. 安卓手机打开 `app/` 里的“智能卡”App
2. 先扫 `TP` 动态请求
3. 直接贴卡/插卡签名，或者转成树莓派静态码
4. 回扫给 `TP`

## 3. 签名后二维码怎么操作

当前固件不是旧版的自动高频轮播，而是更偏向“手动稳扫”。

如果输出只有一张码，会直接显示。

如果输出是多张手动码：

- `右` 或右侧上面键：下一张
- `左` 或右侧中间键：上一张
- `上`：调亮
- `下`：调暗

这套逻辑同时用于：

- 手动切换交易二维码
- 手动切换签名二维码

## 4. `助记词工具`

当前菜单包括：

- `拍照创建助记词`
- `摇骰子创建助记词`
- `导入助记词`
- `BIP39 单词自检`
- `从钢板数字恢复二次助记词`
- `拍照识别钢板/纸张点位`
- `已加载助记词`

### 4.1 `BIP39 单词自检`

当前提供两个入口：

- `输入单词查编号`
- `输入编号查单词`

### 4.2 已加载助记词

当前已加载助记词菜单会根据类型显示：

- `查看助记词`
- `查看 BIP39 序号`
- `派生路径算地址`
- `导出当前助记词 BTC zpub`
- `导出当前助记词 BTC xpub`
- `BIP-85 子助记词`
- `写入当前助记词到智能卡`
- `二次加密助记词`
- `二次还原助记词`
- `转成钢板打孔数字`
- `删除助记词`

只要当前词组支持 `BIP39` 序号显示，相关页面都会尽量给出 `0-2047` 对照，方便人工复核。

### 4.3 `BIP-85 子助记词`

在“已加载助记词”里可以进入：

- `BIP-85 子助记词`

当前支持：

- 选择 `12 / 18 / 24` 词
- 输入 `BIP85 index`
- 查看子助记词
- 查看子助记词的 `BIP39` 序号
- 验证备份
- `完成子助记词`
- `子助记词写入智能卡`

完成后，子助记词会作为一条新的“已加载助记词”保存下来。
这样就可以继续使用当前固件已有的：

- 写入当前助记词到智能卡
- 二次加密助记词
- 二次还原助记词
- 转成钢板打孔数字
- 从钢板数字恢复
- 查看 BIP39 序号

当前默认创建出来的父助记词本身就是标准 `BIP39`，所以可以直接当 `BIP85` 父助记词。
`BIP85` 派生出来的子助记词也是标准 `BIP39`，技术上它也可以再次当新的父助记词，继续派生更多子助记词。

但长期实际使用时，更推荐这样做：

- 固定 1 条主父助记词
- 在这条主父助记词下面用不同 `index` 派生不同子助记词
- 不要长期一层一层继续往下套娃派生

原因很简单：

- 技术上可以继续派生
- 人工管理会越来越容易混淆
- 备份、复查、恢复时更容易出错

如果要长期保存真资金，优先记清楚：

- 哪一条是主父助记词
- 每个子助记词对应的 `词数`
- 每个子助记词对应的 `BIP85 index`
- 子助记词是否已经写入智能卡、做过二次加密、或转成钢板数字

### 4.4 二次加密 / 二次还原 / 钢板流程

当前固件里这几条线都已经有“序号复查”入口：

- 二次加密预览结果序号
- 二次还原预览结果序号
- 钢板数字恢复预览恢复序号
- 钢板打孔数字页查看对应序号

二次加密支持的逐词运算是：

- 加法
- 减法
- 乘法
- 除法

实际保存真资金时，优先用加法/减法，乘法/除法更适合演示和特殊用途。

## 5. `派生路径算地址`

当前默认路径：

- EVM：
  `m/44'/60'/0'/0/0`
- BTC：
  `m/84'/0'/0'/0/0`

路径输入支持常见纠错：

- 弯引号
- 全角斜杠
- `h/H/'`
- 漏写前缀 `m/`

结果页会显示：

- 标准化后的路径
- 地址
- 网络/脚本类型说明
- `显示二维码`

### 5.1 EVM 地址说明

当路径是 `m/44'/60'/...` 这类标准 `60'` 路径时，结果页会给出 `0x` 地址。

这类地址通常可用于：

- `ETH`
- `ARB`
- `Base`
- `OP`
- `BSC`
- `Polygon`

但不同链上的资产和交易彼此独立，不要把“地址相同”理解成“余额共用”。

## 6. `智能卡工具`

当前菜单包括：

- `按路径查看智能卡地址`
- `导出智能卡 BTC zpub`
- `导出智能卡 BTC xpub`
- `写入已加载助记词到智能卡`
- `更改智能卡 PIN`
- `重置智能卡`

### 6.1 按路径查看智能卡地址

支持：

- 标准 BTC 路径
- 标准 EVM 路径

结果页也能：

- 查看地址
- `显示二维码`

### 6.2 导出智能卡 `BTC zpub/xpub`

这两个入口已经从首页挪到“智能卡工具”里了，避免和助记词派生导出混淆。

### 6.3 写入已加载助记词到智能卡

前提：

- 先在“助记词工具”里创建或导入助记词

## 7. `固件完整性自检`

当前功能会核对运行时清单里的关键文件，检测：

- 缺失
- 被修改
- 多出异常文件

适合发现：

- 卡内文件被误删
- 关键脚本被替换
- 被偷偷塞了额外文件

但它不能单靠设备自己证明“整张卡一定没被重刷”。

更稳的做法：

1. 看自检结果
2. 再对照当前镜像的 `.sha256`
3. 再对照 `.build-info.txt`
4. 再确认对应源码 tag

## 8. 常见问题

### 8.1 子助记词还能继续当父助记词吗

可以。

只要这条子助记词本身是标准 `BIP39` 助记词，它就还能继续进入 `BIP-85 子助记词`，再派生下一层子助记词。

但推荐做法不是层层套娃，而是：

- 固定 1 条主父助记词
- 主要依靠不同 `index` 管理不同用途的子助记词

这样以后复查、恢复、人工记账都会更稳。

### 8.2 `BlueWallet` 扫回慢

先试：

- 把树莓派二维码调亮
- 手机别贴太近
- 正对屏幕
- 多张码时按顺序手动切换

### 8.2 为什么没有“官方模式”

因为当前源码里已经去掉了这个入口，首页只保留离线签名器自己的 4 个工具入口。

### 8.3 助记词人工复核时最该看哪里

优先看：

- `查看助记词`
- `查看 BIP39 序号`
- `转成钢板打孔数字`
- `从钢板数字恢复二次助记词`

这几条链路现在都能配合序号做人工复查。
