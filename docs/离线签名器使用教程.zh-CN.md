# 离线签名器使用教程

这份教程完全按当前源码重写，重点只讲现在机器里真实存在的功能。

## 1. 当前首页

树莓派开机后首页标题就是：

- `离线签名器`

首页 4 个入口：

- `扫码签名`
- `助记词工具`
- `固件完整性自检`
- `智能卡工具`

首页左上角没有返回按钮，这是当前代码里的设计。

## 2. `扫码签名` 现在支持什么

### 2.1 自己的安卓观察钱包

适合：

- `wallet/` 生成的 EVM 请求
- `wallet/` 生成的 `BTC PSBT` 请求

流程：

1. 手机显示待签名二维码
2. 树莓派进 `扫码签名`
3. 输入智能卡 `PIN`
4. 树莓派签名
5. 手机扫回并人工确认广播

### 2.2 `BlueWallet`

当前固件已经识别：

- `BBQR`
- `UR`
- 常见 `PSBT` 分片

流程：

1. `BlueWallet` 创建 `BTC` 交易
2. 让它显示待签名 `PSBT`
3. 树莓派扫入
4. 输入智能卡 `PIN`
5. 树莓派回显签名结果
6. `BlueWallet` 扫回并广播

### 2.3 `TokenPocket`

树莓派不直接吃高频 `TP` 动态码。

当前推荐做法：

1. 安卓手机打开 `app/` 里的“智能卡”App
2. 先扫 `TP` 动态请求
3. 直接贴卡/插卡签名，或者转成树莓派静态码
4. 回扫给 `TP`

## 3. 签名后二维码怎么操作

当前固件不是旧版的自动高频轮播，而是更偏向“手动稳扫”。

如果输出只有一张码，会直接显示。

如果输出是多张手动码：

- `右` 或右侧上面键：下一张
- `左` 或右侧中间键：上一张
- `上`：调亮
- `下`：调暗

这套逻辑同时用于：

- 手动切换交易二维码
- 手动切换签名二维码

## 4. `助记词工具`

当前菜单包括：

- `拍照创建助记词`
- `摇骰子创建助记词`
- `导入助记词`
- `BIP39 单词自检`
- `从钢板数字恢复二次助记词`
- `拍照识别钢板/纸张点位`
- `已加载助记词`

### 4.1 `BIP39 单词自检`

当前提供两个入口：

- `输入单词查编号`
- `输入编号查单词`

### 4.2 `导入助记词`

当前支持的常见入口包括：

- 输入 `12 / 15 / 18 / 21 / 24` 个单词助记词
- `按编号导入 BIP39 助记词`
- 扫描 `SeedQR`

如果你选的是：

- `按编号导入 BIP39 助记词`

那每一位输入的都是标准英文词表里的 `0-2047` 编号，不是自定义数字。

适合：

- 你手里只有编号备份
- 你想对照 `BIP39` 单词表人工复核

### 4.3 导入后查看 `BIP39` 原始熵

如果当前这条助记词是标准英文 `BIP39`，加载后现在还可以查看：

- `查看原始熵(HEX)`

它显示的是这条助记词对应的原始熵，不是骰子串。

长度规则：

- `12` 词 = `128 bit` = `32` 个十六进制字符
- `18` 词 = `192 bit` = `48` 个十六进制字符
- `24` 词 = `256 bit` = `64` 个十六进制字符

如果你以后想拿去 `BIP39` 网站复核，注意：

- 要用“原始熵 / entropy / HEX”那一类输入方式
- 不是网站的 `Dice` 模式
- 同一份 `HEX` 熵，生成出来的助记词会一样

### 4.4 已加载助记词

当前已加载助记词菜单会根据类型显示：

- `查看助记词`
- `查看 BIP39 序号`
- `查看原始熵(HEX)`
- `派生路径算地址`
- `导出当前助记词 BTC zpub`
- `导出当前助记词 BTC xpub`
- `BIP-85 子助记词`
- `写入当前助记词到智能卡`
- `写入当前助记词到 SeedKeeper`
- `二次加密助记词`
- `二次还原助记词`
- `转成钢板打孔数字`
- `删除助记词`

只要当前词组支持 `BIP39` 序号显示，相关页面都会尽量给出 `0-2047` 对照，方便人工复核。

但也要注意：

- `Electrum`
- `SLIP39`
- `Aezeed`

这类不是标准英文 `BIP39` 的词组，不一定能显示 `BIP39` 序号或原始熵。

如果是标准 `BIP39` 助记词，`查看原始熵(HEX)` 页面里现在还可以直接：

- `显示二维码`

手机扫这个二维码后，拿到的就是原始熵 `HEX`，可以直接贴进 `BIP39` 网站的原始熵输入框做人工复核。

### 4.5 `BIP-85 子助记词`

在“已加载助记词”里可以进入：

- `BIP-85 子助记词`

当前支持：

- 选择 `12 / 18 / 24` 词
- 输入 `BIP85 index`
- 查看子助记词
- 查看子助记词的 `BIP39` 序号
- 验证备份
- `完成子助记词`
- `子助记词写入智能卡`
- `子助记词写入 SeedKeeper`

完成后，子助记词会作为一条新的“已加载助记词”保存下来。
这样就可以继续使用当前固件已有的：

- 写入当前助记词到智能卡
- 二次加密助记词
- 二次还原助记词
- 转成钢板打孔数字
- 从钢板数字恢复
- 查看 BIP39 序号

当前默认创建出来的父助记词本身就是标准 `BIP39`，所以可以直接当 `BIP85` 父助记词。
`BIP85` 派生出来的子助记词也是标准 `BIP39`，技术上它也可以再次当新的父助记词，继续派生更多子助记词。

但长期实际使用时，更推荐这样做：

- 固定 1 条主父助记词
- 在这条主父助记词下面用不同 `index` 派生不同子助记词
- 不要长期一层一层继续往下套娃派生

原因很简单：

- 技术上可以继续派生
- 人工管理会越来越容易混淆
- 备份、复查、恢复时更容易出错

如果要长期保存真资金，优先记清楚：

- 哪一条是主父助记词
- 每个子助记词对应的 `词数`
- 每个子助记词对应的 `BIP85 index`
- 子助记词是否已经写入智能卡、做过二次加密、或转成钢板数字

### 4.6 二次加密 / 二次还原 / 钢板流程

当前固件里这几条线都已经有“序号复查”入口：

- 二次加密预览结果序号
- 二次还原预览结果序号
- 钢板数字恢复预览恢复序号
- 钢板打孔数字页查看对应序号

二次加密支持的逐词运算是：

- 加法
- 减法
- 乘法
- 除法

实际保存真资金时，优先用加法/减法，乘法/除法更适合演示和特殊用途。

## 5. `派生路径算地址`

当前默认路径：

- EVM：
  `m/44'/60'/0'/0/0`
- BTC：
  `m/84'/0'/0'/0/0`

路径输入支持常见纠错：

- 弯引号
- 全角斜杠
- `h/H/'`
- 漏写前缀 `m/`

结果页会显示：

- 标准化后的路径
- 地址
- 网络/脚本类型说明
- `显示二维码`

### 5.1 EVM 地址说明

当路径是 `m/44'/60'/...` 这类标准 `60'` 路径时，结果页会给出 `0x` 地址。

这类地址通常可用于：

- `ETH`
- `ARB`
- `Base`
- `OP`
- `BSC`
- `Polygon`

但不同链上的资产和交易彼此独立，不要把“地址相同”理解成“余额共用”。

## 6. `智能卡工具`

当前顶层只保留 3 个入口：

- `Satochip 功能`
- `SeedKeeper 功能`
- `完整智能卡菜单`

如果你只想日常用，优先点前两个分开的入口；只有你需要看卡信息、剩余空间、描述符、克隆等更杂的能力时，再进：

- `完整智能卡菜单`

### 6.1 `Satochip 功能`

这里放的是偏签名卡的功能：

- `按路径查看 Satochip 地址`
- `导出 Satochip BTC zpub`
- `导出 Satochip BTC xpub`
- `写入已加载助记词到 Satochip`
- `更改 Satochip PIN`
- `重置 Satochip`
- `更多 Satochip 功能`

#### 按路径查看 Satochip 地址

支持：

- 标准 BTC 路径
- 标准 EVM 路径

结果页也能：

- 查看地址
- `显示二维码`

#### 导出智能卡 `BTC zpub/xpub`

这两个入口现在明确属于 `Satochip`，已经从首页挪到“智能卡工具”里，避免和助记词派生导出混淆。

### 6.2 `SeedKeeper 功能`

这里放的是偏秘密管理的功能：

- `卡上真随机创建助记词`
- `写入已加载助记词到 SeedKeeper`
- `保存二次加密助记词到 SeedKeeper`
- `从 SeedKeeper 加载二次加密助记词`
- `更改 SeedKeeper PIN`
- `重置 SeedKeeper`
- `更多 SeedKeeper 功能`

#### 保存二次加密助记词到 SeedKeeper

如果你已经在树莓派里完成了“二次加密 / 假助记词”流程，现在可以直接把这组假的助记词文本保存到 `SeedKeeper`。

适合：

- 不想只靠纸或钢板记假助记词
- 想把钢板/二次加密恢复链路再留一份卡内备份

当前保存的是：

- 二次加密后的假助记词文本
- 不会覆盖你卡里原来已经存在的 `SeedKeeper` 其他秘密

#### 从 SeedKeeper 加载二次加密助记词

如果你之前把“二次加密后的假助记词”保存进过 `SeedKeeper`，现在可以直接从这里读回到树莓派。

读回后会自动进入当前固件的钢板/二次还原缓存，后续你就可以继续：

- `查看`
- `查看 BIP39 序号`
- `钢板转数字`
- `数字转钢板`
- `二次还原`

### 6.3 直接写入卡内 applet

前提：

- 先在“助记词工具”里创建或导入助记词

当前已加载助记词里可以直接做两种写入：

- `写入当前助记词到智能卡`
- `写入当前助记词到 SeedKeeper`

如果是 `BIP85` 子助记词流程，完成前也可以直接：

- `子助记词写入智能卡`
- `子助记词写入 SeedKeeper`

### 6.4 `SeedKeeper` 真随机创建助记词

现在有两条入口：

- `助记词工具` 里的第一个入口：`智能卡真随机创建助记词`
- `智能卡工具 -> SeedKeeper 功能 -> 卡上真随机创建助记词`

流程：

1. 贴卡或插卡，确保这张卡里已经装有 `SeedKeeper`
2. 选择 `12 / 15 / 18 / 21 / 24` 词长度
3. 固件向 `SeedKeeper` 请求卡内真随机熵
4. 直接在树莓派里生成标准 `BIP39` 助记词并加载到助记词菜单

生成完成后，继续在已加载助记词里就可以：

- `查看助记词`
- `查看 BIP39 序号`
- `查看原始熵(HEX)`
- `显示二维码`
- `写入当前助记词到 Satochip`
- `写入当前助记词到 SeedKeeper`

这里显示的原始熵是标准 `BIP39` 原始熵 `HEX`，不是骰子 `1-6` 数字串。
如果把同一份 `HEX` 熵贴到 `BIP39` 网站的原始熵输入框，生成出来的助记词会一样。

## 6.5 `SeedKeeper` 和 `SatochipApplet` 别混

当前你在树莓派固件里看到的“智能卡工具”，既可以处理 `SatochipApplet`，也可以直接进入 `SeedKeeper` 功能。

要记住：

- `SatochipApplet`：偏签名、派生地址、公钥、`xpub/zpub`
- `SeedKeeper`：偏秘密管理

当前这套树莓派固件能做的是：

- 从 `SeedKeeper` 导入助记词
- 用 `SeedKeeper` 真随机创建助记词
- 使用 `Satochip` 卡
- 给 `Satochip` 卡写入当前助记词
- 给 `SeedKeeper` 写入当前助记词
- 把二次加密后的假助记词保存到 `SeedKeeper`
- 从 `SeedKeeper` 把假助记词读回树莓派继续二次还原
- 用 `Satochip` 卡签名、导出地址和 `xpub/zpub`
- 分别更改 `Satochip PIN / SeedKeeper PIN`
- 分别重置 `Satochip / SeedKeeper`
- 进入 `SeedKeeper` 功能菜单，做查看秘密、保存密码、删除秘密、描述符读写、克隆、查看剩余空间

当前不能直接做的是：

- 给白卡安装 `SatochipApplet`
- 给白卡安装 `SeedKeeper`
- 在同一张卡上来回切换两种 applet

如果你用 `java -jar gp.jar --list` 已经能看到：

- `APP: 5361746F4368697000 (SELECTABLE)`
- `APP: 536565644B656570657200 (SELECTABLE)`

那就说明同一张卡已经同时装好了两个 applet。
此时最稳的做法不是再重刷，而是直接在当前固件里分别使用它们对应的功能。

如果你想把这件事彻底弄明白，直接看：

- [SeedKeeper 与 SatochipApplet 分工指南](SeedKeeper与SatochipApplet分工指南.zh-CN.md)

## 7. `固件完整性自检`

当前功能会核对运行时清单里的关键文件，检测：

- 缺失
- 被修改
- 多出异常文件

适合发现：

- 卡内文件被误删
- 关键脚本被替换
- 被偷偷塞了额外文件

但它不能单靠设备自己证明“整张卡一定没被重刷”。

更稳的做法：

1. 看自检结果
2. 再对照当前镜像的 `.sha256`
3. 再对照 `.build-info.txt`
4. 再确认对应源码 tag

## 8. 常见问题

### 8.1 子助记词还能继续当父助记词吗

可以。

只要这条子助记词本身是标准 `BIP39` 助记词，它就还能继续进入 `BIP-85 子助记词`，再派生下一层子助记词。

但推荐做法不是层层套娃，而是：

- 固定 1 条主父助记词
- 主要依靠不同 `index` 管理不同用途的子助记词

这样以后复查、恢复、人工记账都会更稳。

### 8.2 `BlueWallet` 扫回慢

先试：

- 把树莓派二维码调亮
- 手机别贴太近
- 正对屏幕
- 多张码时按顺序手动切换

### 8.2 为什么没有“官方模式”

因为当前源码里已经去掉了这个入口，首页只保留离线签名器自己的 4 个工具入口。

### 8.3 助记词人工复核时最该看哪里

优先看：

- `查看助记词`
- `查看 BIP39 序号`
- `转成钢板打孔数字`
- `从钢板数字恢复二次助记词`

这几条链路现在都能配合序号做人工复查。
