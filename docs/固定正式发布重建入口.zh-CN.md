# 固定正式发布重建入口

这页只做一件事：以后不让人靠记忆重建正式发布件。

以后无论是你自己，还是新的 AI，只要先跑这个脚本，就不会先去猜 `main`、猜 tag、猜命令。

## 1. 先列出当前官方重建目标

```bash
bash scripts/rebuild_official_release.sh --list
```

它会直接列出：

- 当前 clean 正式树莓派固件
- 当前正式安卓观察钱包
- 对应的 release tag
- 对应的源码冻结 tag

## 2. 重建当前 clean 正式固件

```bash
bash scripts/rebuild_official_release.sh firmware-clean
```

这个入口会自动：

- 使用 `release-manifest.json` 里固定的 `offline-signer-clean-source-20260410b`
- 在临时 `git worktree` 里重建
- 默认启用低负载参数
- 重建后自动校验产物和官方记录是否一致

## 3. 重建当前正式钱包 APK

```bash
bash scripts/rebuild_official_release.sh wallet-release
```

这个入口会自动：

- 使用 `release-manifest.json` 里固定的 `wallet-android-20260408-0.1.4-source`
- 在临时 `git worktree` 里重建
- 默认限制 Gradle 内存和 worker 数
- 重建后自动校验 APK、`sha256`、`build-info`

## 4. 单独验当前正式件

```bash
bash scripts/check_named_release.sh firmware-clean
bash scripts/check_named_release.sh wallet-release
```

这两条会直接核对：

- 正式产物 hash
- `build-info` 里的 `repo_head`
- 对应源码冻结 tag
- 固件的 `repo_dirty/build_clean_mode`
- 钱包的 `version_name`

## 5. 最重要的规则

- 不要直接拿 `main` 重建正式发布版
- 不要再靠脑子记 release tag 和 source tag
- 以后先看 `release-manifest.json`
- 以后先跑 `scripts/rebuild_official_release.sh`

如果这套脚本和清单都过了，再谈“这次重建是不是和官方正式件一致”。

## 6. 以后想编出一模一样的正式件，最短记法

只记住这 2 条：

1. 固件和钱包正式件，都先用 `scripts/rebuild_official_release.sh`
2. 重建完以后，再用 `scripts/check_named_release.sh` 验

也就是：

```bash
bash scripts/rebuild_official_release.sh firmware-clean
bash scripts/check_named_release.sh firmware-clean

bash scripts/rebuild_official_release.sh wallet-release
bash scripts/check_named_release.sh wallet-release
```

### 6.1 树莓派固件

树莓派固件想和 GitHub 上当前正式件对上，核心条件已经固定在仓库里：

- 固定源码冻结 tag
- 固定构建脚本
- 固定低负载默认参数
- 固定 `.sha256`
- 固定 `build-info`

只要按这套入口走，就不是靠运气碰哈希。

### 6.2 安卓正式钱包

安卓正式钱包想编出和当前发布版 `sha256` 完全一样，还必须保住：

- 正式签名 keystore
- `wallet/keystore.properties`
- `storePassword / keyAlias / keyPassword`

这部分不会放到 GitHub，所以以后换电脑前一定要看：

- [非 GitHub 关键备份清单](非GitHub关键备份清单.zh-CN.md)
