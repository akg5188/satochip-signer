# 固定正式发布重建入口

这页只做一件事：以后不让人靠记忆重建正式发布件。

以后无论是你自己，还是新的 AI，只要先跑这个脚本，就不会先去猜 `main`、猜 tag、猜命令。

## 1. 先列出当前官方重建目标

```bash
bash scripts/rebuild_official_release.sh --list
```

它会直接列出：

- 当前 clean 树莓派固件（跟随 HEAD）
- 当前正式安卓观察钱包
- 对应的 release tag
- 对应的源码来源

## 2. 重建当前 clean 正式固件

```bash
bash scripts/rebuild_official_release.sh firmware-clean
```

这个入口会自动：

- 使用 `release-manifest.json` 里当前 `firmware-clean` 指向的 `HEAD`
- 在临时 `git worktree` 里重建
- 默认启用低负载参数
- 重建后自动校验产物和当前 `HEAD` / clean 规则是否一致
- 如果当前工作区还有未提交的源码或脚本改动，会直接拒绝，避免你误以为正式件已经带上“最新功能”

注意：

- 这条命令的目标是“按当前 `HEAD` 重建新的 clean 基线”
- 它不等于“仓库里当前已经保留的 `dist/system-update-latest.*` 一定就是当前 `HEAD` 刚编出来的”
- 当前仓库里保留的这份 `dist/system-update-latest.*`，真实来源以它自己的 `build-info` 为准

如果你要重建历史公开固件 `offline-signer-firmware-20260410b-clean`，改用：

```bash
bash scripts/rebuild_official_release.sh firmware-public-20260410b-clean
```

## 3. 重建当前正式钱包 APK

```bash
bash scripts/rebuild_official_release.sh wallet-release
```

这个入口会自动：

- 使用 `release-manifest.json` 里当前 `wallet-release` 指向的 `HEAD`
- 在临时 `git worktree` 里重建
- 默认限制 Gradle 内存和 worker 数
- 重建后自动校验 APK、`sha256`、`build-info`
- 如果当前工作区还有未提交的构建相关改动，也会直接拒绝，避免你误以为正式钱包已经带上最新改动

## 4. 单独验当前正式件

```bash
bash scripts/check_named_release.sh firmware-clean
bash scripts/check_named_release.sh wallet-release
```

这两条会直接核对：

- 正式产物 hash
- `build-info` 里的 `repo_head`
- 对应源码来源
- 固件的 `repo_dirty/build_clean_mode`
- 钱包的 `version_name`

补充：

- `check_named_release.sh firmware-clean`
  适合校验“你刚按当前 `HEAD` 重建出来的 clean 固件”
- 如果你只是想核对仓库里当前保留的 `dist/system-update-latest.*` 自己有没有坏，优先看它的 `.sha256` 和 `.build-info.txt`
- GitHub 上对应的自动校验工作流也是按“资产自洽”来做，不会把当前仓库保留基线误判成“必须等于当前 `HEAD`”

## 5. 最重要的规则

- 不要再让固件发布入口偷偷回到老 tag
- 不要再靠脑子记 release tag 和 source tag
- 以后先看 `release-manifest.json`
- 以后先跑 `scripts/rebuild_official_release.sh`
- 如果你还没提交新功能，别硬跑 `firmware-clean`，直接用 `bash scripts/build_current_firmware.sh`

如果这套脚本和清单都过了，再谈“这次重建是不是当前 HEAD 的 clean 固件”。

## 6. 以后想编出一模一样的正式件，最短记法

只记住这 2 条：

1. 固件和钱包正式件，都先用 `scripts/rebuild_official_release.sh`
2. 重建完以后，再用 `scripts/check_named_release.sh` 验

也就是：

```bash
bash scripts/rebuild_official_release.sh firmware-clean
bash scripts/check_named_release.sh firmware-clean

bash scripts/rebuild_official_release.sh wallet-release
bash scripts/check_named_release.sh wallet-release
```

### 6.1 树莓派固件

树莓派固件现在分成两类：

- 当前 `HEAD` clean 固件：
  `bash scripts/rebuild_official_release.sh firmware-clean`
- 当前仓库保留的固件基线：
  `current-head-clean`
- 历史 `20260410b` 冻结正式件：
  `bash scripts/rebuild_official_release.sh firmware-public-20260410b-clean`

这样以后默认不会再编回老固件；真要追老公开包时，再显式选历史 profile。
如果你只是要找 GitHub 上当前仓库保留的那份已编好镜像，就看 `current-head-clean`。

### 6.2 安卓正式钱包

安卓正式钱包想编出和当前发布版 `sha256` 完全一样，还必须保住：

- 正式签名 keystore
- `wallet/keystore.properties`
- `storePassword / keyAlias / keyPassword`

这部分不会放到 GitHub，所以以后换电脑前一定要看：

- [非 GitHub 关键备份清单](非GitHub关键备份清单.zh-CN.md)
