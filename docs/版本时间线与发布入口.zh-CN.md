# 版本时间线与发布入口

这页只回答 4 个问题：

- 现在 GitHub Releases 里哪几个入口是当前该用的
- 哪些包只是历史归档，不要误刷
- 固件二进制到底对应哪份源码 tag
- 以后发版时，名字和 tag 应该怎么理解

## 2. 树莓派固件为什么有两条线

### 当前 clean 正式线

- 代表包：
  `system-update-latest.img.xz`
- 适合：
  你现在日常真机使用，也是以后复现和验包的首选基线
- 特点：
  功能已收口到当前正式版，`build-info` 为 clean 新格式
- 注意：
  精确源码看 `offline-signer-clean-source-20260401`

### 历史功能验证线

- 代表包：
  `system-update-offline-signer-review-pinless.img.xz`
- 适合：
  回滚排障、对照历史功能
- 特点：
  功能已验证，但不是 clean 正式基线
- 注意：
  它的 `build-info` 是 `repo_dirty=1`、`build_clean_mode=no-clean`

## 3. 历史包怎么识别

GitHub Releases 里，下面这些命名现在都视为历史归档：

- `Offline Signer Firmware 2026-03-18 (historical)`
- `Offline Signer Firmware 2026-03-24 (historical)`
- `Offline Signer Firmware 2026-03-27 (historical)`
- `Offline Signer Firmware 2026-03-27-2 (historical)`
- `Satochip Wallet Android 2026-03-18 (historical preview)`
- `Satochip Wallet Android 2026-03-28 (historical)`
- `Satochip Wallet Android 2026-03-28 21:12 (historical old signing key)`
- `Smartcard App Android 2026-03-16 (historical preview)`
- `Smartcard App Android 2026-03-18 19:56 (historical)`

这些包保留的意义主要是：

- 追溯当时的界面和功能
- 回滚排障
- 对照历史文档

不要默认把它们当成“当前推荐下载”。

## 4. 固件和源码怎么对应

最容易弄错的一点是：

- GitHub `main`
- 某张历史固件
- 某个 release tag

这三者经常不是同一个提交。

当前最重要的对应关系：

- `offline-signer-firmware-20260401-clean`
  - 固件 release tag
  - 对应当前 clean 正式包
  - 精确源码看：
    `offline-signer-clean-source-20260401`

- `offline-signer-firmware-20260401-review-pinless`
  - 固件 release tag
  - 对应历史功能验证包
  - 精确源码看：
    `offline-signer-review-pinless-source-20260401`

详细字段看：

## 5. 下次该怎么选

### 想直接使用

- 先下：
  `offline-signer-firmware-20260401-clean`

### 想做复现或长期基线保存

- 先看：
  `offline-signer-firmware-20260401-clean`

### 想继续开发新功能

- 看：
  `main`
- 但不要把 `main` 直接当成任意历史二进制的精确来源

## 6. 以后看到这些名字时怎么理解

- `offline-signer-firmware-*`
  树莓派离线签名器固件 release
- `offline-signer-clean-source-*`
  当前 clean 正式固件的精确冻结源码 tag
- `offline-signer-review-pinless-source-*`
  历史 `review-pinless` 功能包的精确冻结源码 tag
- `smartcard-app-android-*`
  安卓“智能卡”App release
- `wallet-android-*`
  安卓观察钱包 release
- `j3r180-card-firmware-*`
  智能卡固件 release

如果以后又出了新固件，最稳的做法还是：

1. 先看 GitHub Releases
2. 再看这页确认它属于哪条线
3. 最后去看对应源码 tag，而不是直接猜 `main`
