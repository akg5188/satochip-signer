# 独立钱包扩展到 BTC 与闪电网络方案

这份文档现在改成“规划说明”，不再把未来能力写得像当前已经实现。

## 1. 当前源码已经做到哪里

按当前 `wallet/` 与树莓派源码，已经真实存在的是：

- `Arbitrum One` 观察钱包
- 树莓派 EVM 冷签
- `WalletConnect v2`
- `BTC xpub / ypub / zpub` 观察账户原型
- `BTC PSBT` 冷签请求准备与广播

还没有完成的是：

- 完整多链 EVM 钱包
- 闪电网络
- 内置 DApp 浏览器

## 2. 为什么闪电网络不能直接硬塞进当前主流程

因为当前主流程是：

- 手机准备请求
- 树莓派离线签名
- 手机扫回结果再广播

而闪电网络更像：

- 节点持续在线
- 通道状态持续同步
- 会话型支付

所以它不适合直接沿用现在这套“单次二维码冷签”的主通路。

## 3. 当前仍然推荐的路线

### 第一步：把 BTC 链上继续做完整

优先补齐：

- 更完整的 BTC 观察账户体验
- 更多地址类型和账户管理
- 更稳的 `PSBT` 工作流

### 第二步：把闪电网络设计成单独在线模块

推荐方向：

- 手机端做前端与状态展示
- 真实闪电能力接外部节点或服务
