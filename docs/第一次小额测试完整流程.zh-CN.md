# 第一次小额测试完整流程

这份教程是写给第一次真正动手的人看的。

目标不是一次就发大额资产，而是：

- 先用一笔很小的测试金额，把整条流程跑通

如果你是第一次用这套方案，强烈建议先做这件事。

如果你更适合看图照着点，先看：

- [逐屏示意图版第一次上手教程（临时）](逐屏截图版第一次上手教程.zh-CN.md)
- [真机实拍逐屏截图采集清单](真机实拍逐屏截图采集清单.zh-CN.md)

## 1. 为什么一定先做小额测试

因为第一次最容易出问题的地方，通常不是“代码坏了”，而是：

- 你还不熟悉流程
- 你还不熟悉哪张卡干什么
- 你还不熟悉手机和树莓派之间怎么来回扫

所以最稳的办法是：

- 先用一笔你完全能接受丢失或卡住的小额金额练流程

## 2. 这份测试最推荐走哪条路

对第一次上手的人，我最推荐这条：

1. 树莓派已经能正常开机
2. 一张 `Satochip` 卡已经初始化好
3. 手机装好自己的安卓观察钱包
4. 用自己的安卓观察钱包做第一笔小额测试

原因：

- 这条线最完整
- 也最接近以后日常长期使用

如果你暂时不用自己的安卓观察钱包，也可以看后面的：

- `BlueWallet` 小额测试分支

## 3. 开始前必须准备好的东西

### 3.1 设备

- 树莓派设备
- 一张刷好正式固件的 `TF` 卡
- 一张已经初始化好的 `Satochip` 卡
- 一台安卓手机

### 3.2 你自己必须知道的东西

- 树莓派登录密码
- 卡的 `PIN`
- 这张卡到底是不是你准备用来签名的那张

### 3.3 资金准备

只准备：

- 一笔很小的测试金额

不要第一次就拿大额做测试。

## 4. 测试前先做这 6 个确认

1. 树莓派能开机并进入首页
2. 首页能看到 `扫码签名 / 助记词工具 / 固件完整性自检 / 智能卡工具`
3. 你知道当前这张卡的 `PIN`
4. 你确认这张卡不是拿来乱重置的老主力卡
5. 手机能正常安装和打开 App
6. 你准备的是小额测试金额，不是大额正式交易

## 5. 推荐主线：自己的安卓观察钱包做第一笔测试

### 5.1 第一步：确认卡和树莓派本身没问题

在树莓派里先做最简单验证：

1. 进入 `智能卡工具`
2. 进入 `Satochip 功能`
3. 尝试查看地址，或者导出 `BTC xpub / zpub`

如果这一步都做不通，先不要继续往手机交易那边走。

### 5.2 第二步：给手机导入观察账户

如果你要测比特币：

1. 在树莓派里导出 `BTC xpub / zpub`
2. 打开安卓观察钱包
3. 进入 `BTC` 模式
4. 用扫码或粘贴方式导入

如果你要测 `Arbitrum` 这类链：

1. 在手机里添加观察地址
2. 确认首页能正常显示这个地址

### 5.3 第三步：先等同步正常

如果是比特币：

- 等余额
- 等最近活动
- 等下一收款地址

至少要先确认：

- 手机不是空白状态
- 账户已经真的导入成功

### 5.4 第四步：准备一笔很小的测试交易

无论哪条链，原则都一样：

- 金额选很小
- 地址选你自己能确认的地址

如果是比特币：

- 在手机里准备 `PSBT`

如果是 `Arbitrum`：

- 在手机里准备一笔最简单的转账请求

### 5.5 第五步：手机显示待签名二维码

你现在应该看到的是：

- 手机上显示一组待签名二维码

这时先别急着签，先确认：

- 这是你刚才自己准备的那笔交易

### 5.6 第六步：树莓派扫码

在树莓派里：

1. 进入 `扫码签名`
2. 对准手机二维码
3. 等树莓派解析完成

### 5.7 第七步：在树莓派上核对关键信息

这里重点看：

- 金额
- 收款地址
- 手续费

只要有一项明显不对，就先停。

### 5.8 第八步：输入卡 `PIN`

确认内容没问题后：

1. 输入当前签名卡的 `PIN`
2. 完成签名

### 5.9 第九步：手机扫回结果

签名成功后，树莓派会显示结果二维码。

这时：

1. 用手机扫回
2. 手机拿到已签名结果

### 5.10 第十步：手机人工确认广播

这一步非常重要：

- 手机不会因为扫回结果就自动替你发出去

你要自己再确认一次：

- 金额对不对
- 地址对不对
- 这确实是你要发的测试交易

确认无误后再点：

- 广播

### 5.11 第十一步：确认这笔测试真的成功

至少确认这 3 件事：

1. 手机里显示广播成功
2. 能查到这笔交易
3. 你知道这条完整流程已经走通了

## 6. `BlueWallet` 小额测试分支

如果你第一次想测的是：

- `BlueWallet + 树莓派 + 比特币`

那按这条做。

### 6.1 先准备好 `BlueWallet` 观察钱包

先确保：

- `BlueWallet` 里已经成功导入观察账户
- 能看到余额

### 6.2 发起一笔很小的比特币交易

原则还是一样：

- 只做小额
- 地址自己确认

### 6.3 `BlueWallet` 显示 `PSBT`

这时：

1. 树莓派进入 `扫码签名`
2. 树莓派扫描 `BlueWallet` 的二维码
3. 输入卡 `PIN`
4. 树莓派返回已签名结果二维码
5. `BlueWallet` 扫回
6. `BlueWallet` 广播

### 6.4 如果广播页面太长怎么办

有时 `BlueWallet` 会把交易显示成一大段长字符。

如果按钮被挤没：

1. 先复制交易
2. 再去广播入口粘贴广播

不要因为页面长就以为签名坏了。

## 7. `TokenPocket` 小额测试分支

如果你想先测试：

- `TokenPocket + 安卓智能卡 App + 智能卡`

那按这条做。

### 7.1 最短流程

1. 在 `TokenPocket` 发起一笔简单的小额请求
2. 打开安卓“智能卡”App
3. 扫 `TP` 请求二维码
4. 输入卡 `PIN`
5. 解锁
6. 核对摘要
7. 贴卡或插读卡器签名
8. 让 `TP` 扫回结果

### 7.2 如果树莓派更好扫

那就改走：

1. 安卓“智能卡”App 先扫 `TP` 动态码
2. 它生成树莓派静态中转二维码
3. 让树莓派扫描并签名

## 8. 小额测试成功后，下一步最推荐做什么

成功以后，不要立刻加复杂度。

推荐顺序：

1. 再做第二笔小额测试
2. 确认你真的记住树莓派登录密码和卡 `PIN`
3. 确认你分得清 `SeedKeeper` 和 `Satochip`
4. 再去研究 `BIP85`
5. 再去研究钢板数字、二次加密这些高级功能

## 9. 小额测试失败时，先按哪种情况排查

### 9.1 树莓派根本扫不到

先检查：

- 手机亮度够不够
- 二维码是不是停留太快
- 距离是不是太近或太远

### 9.2 树莓派扫到了，但内容看起来不对

先停，不要签。

重点重新检查：

- 是不是打开了错误的钱包
- 是不是准备了错误的收款地址
- 是不是其实不是你刚才那笔交易

### 9.3 树莓派要求 `PIN`，但签名失败

先检查：

- `PIN` 是否输错
- 你拿的是不是正确那张卡
- 这张卡是不是本来就不是用来签这笔交易的

### 9.4 树莓派已经显示结果，但手机扫不回

先检查：

- 手机相机是否正常
- 树莓派二维码是否太暗
- 是否需要保持更久对准动画二维码

### 9.5 手机扫回了，但不敢点广播

这时很好，说明你还保持谨慎。

只要再核对：

- 金额
- 地址
- 手续费

都对，再点广播。

## 10. 第一次测试完成后，最好记下来这几件事

以后最容易忘的是：

- 你用的是哪张卡
- 这张卡的用途是什么
- 这次测试走的是哪条链路
- 哪个钱包负责准备交易
- 哪个设备负责签名

建议至少记：

1. 用的是 `Satochip` 还是 `SeedKeeper`
2. 用的是自己的安卓观察钱包、`BlueWallet`，还是 `TokenPocket`
3. 哪一步最容易卡住
4. 这次已经被你验证成功的主流程是哪一条

## 11. 如果你现在还不敢开始

那就先只做这 4 步：

1. 树莓派正常开机
2. 树莓派能进入首页
3. 卡能正常被识别
4. 手机能导入观察账户

先把这 4 步做通，再开始真正的小额签名测试。
