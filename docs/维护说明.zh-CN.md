## 3. 当前树莓派构建规则

统一用：

```bash
bash scripts/build_pi_firmware_from_snapshot.sh
bash scripts/check_release_artifacts.sh
```

当前规则：

- `system-update-latest` 只能由干净仓库 + `clean` 构建覆盖
- 当前工作区测试包统一走 `system-update-worktree-latest.*`
- `no-clean` 只给测试，不给正式基线
- 不要再让 `build_current_firmware.sh` 去覆盖 `system-update-latest.*`

## 4. 安卓构建规则

### `app/`

```bash
bash scripts/build_tp_relay_apk.sh
```

说明：

- 可以没有 keystore
- 没有时会回退到 debug 签名

### `wallet/`

```bash
bash scripts/build_current_wallet_apk.sh
bash scripts/rebuild_official_release.sh wallet-release
```

说明：

- `build_current_wallet_apk.sh` 产出当前工作区最新测试包
- `rebuild_official_release.sh wallet-release` 重建当前 `HEAD` 的 clean 正式版
- `release` 必须有 `wallet/keystore.properties`
- 没有会直接失败

## 5. `dist/` 里的东西怎么理解

当前仓库里要重点分清：

- `system-update-latest.*`
  当前 clean 基线固件名及其校验与 `build-info`
- `system-update-worktree-latest.*`
  当前工作区测试固件名；允许带未提交改动或 `no-clean`
- `satochip-wallet-release.*`
  当前 clean 正式钱包 APK 及其校验
- `satochip-wallet-worktree-latest.*`
  当前工作区最新钱包测试 APK 及其校验
- `tp-qr-relay-android-latest.apk`
  默认按需构建，不保证长期常驻 `dist/`

以后判断 APK 是不是最新重编，不要只看文件名。

一定先看：

- `dist/*.build-info.txt` 里的 `repo_head`
- `build_script`
- `build_time_utc`

当前 `check_release_artifacts.sh` 也会对可选 APK 给出额外警告：

- 如果 `repo_head` 不是当前 `HEAD`
- 如果 `build_script` 不是标准入口脚本

## 6. 提交顺序建议

每次发布型改动建议拆成两步：

1. 先提源码和文档
2. 再提 `dist/` 产物

这样以后更容易看清：

- 哪个源码提交产出了哪张固件或 APK
- 哪个提交只是把产物回填进仓库

## 7. 每次发版前至少检查什么

```bash
git status
```

重点别把这些无脑带进去：

- `logs/`
- `local.properties`
- `wallet/local.properties`
- `seedsigner-os/output/`
- `seedsigner-os/buildroot_dl/`
