这份文档是给以后继续维护这个项目用的。

如果你现在只是要快速找到入口，请优先看：

- [长期维护总入口](长期维护总入口.zh-CN.md)
- [安卓构建环境准备](安卓构建环境准备.zh-CN.md)

## 1. 安卓 App 重新编译

TP 签名中转 APK：

```bash
bash scripts/build_tp_relay_apk.sh
```

独立钱包 APK：

```bash
bash scripts/build_wallet_release.sh
```

第一次换机器或重装系统，先看：

- [安卓构建环境准备](安卓构建环境准备.zh-CN.md)

## 3. 当前固件的重打方式

当前树莓派固件不要再按“临时重打 overlay”理解了。

以后统一使用已经验证过的完整脚本：

```bash
bash scripts/build_pi_firmware_from_snapshot.sh
```

它会同时完成：

1. 用当前仓库里冻结好的 `rootfs-overlay/opt` 运行时快照完整构建
2. 生成原始镜像，默认位置是 `TP_ASCII_BASE/images/seedsigner_os.dev_.pi0-smartcard.img`
3. 自动更新 `dist/system-update-latest.img.xz`
4. 自动更新 `sha256` 和 `build-info`

关键点：

- `rootfs-overlay/opt` 现在必须长期保留在仓库里
- 构建快照时间看：
  `seedsigner-os/opt/rootfs-overlay/opt/src/.build_commit_time`
- 默认会用低优先级和固定并发，避免再次把电脑拖死

完整说明看：

- [树莓派固件构建与备份](树莓派固件构建与备份.zh-CN.md)

## 4. 固件发布

正常情况下，不需要再手动计算树莓派固件的 `sha256`。

`bash scripts/build_pi_firmware_from_snapshot.sh` 会自动更新：

- `dist/system-update-latest.img.xz`
- `dist/system-update-latest.img.xz.sha256`
- `dist/system-update-latest.build-info.txt`

只有在你补做历史文件或单独校验时，才手动跑：

```bash
cd dist
sha256sum system-update-latest.img.xz > system-update-latest.img.xz.sha256
```

## 5. 安卓 App 发布文件

当前安卓产物统一使用这些目标稳定文件名：

- `dist/satochip-wallet-release.apk`
- `dist/satochip-wallet-release.apk.sha256`
- `dist/satochip-wallet-release.build-info.txt`

TP 中转 APK 现在默认按需构建，不再长期保留在仓库 `dist/` 快照里；需要时先运行：

```bash
bash scripts/build_tp_relay_apk.sh
```

如果某个安卓文件当前不在仓库里，先重新构建生成，再决定是否回填到仓库和 Release。

## 6. Git 提交建议

每次发布前至少检查：

```bash
git status
```

重点确认不要把这些推上去：

- `logs/`
- `*.deb`
- `local.properties`
- `seedsigner-os/buildroot_dl/`
- `seedsigner-os/output/`

## 7. 这套架构的关键点

1. 手机负责吃掉 TP 高频动态码。
2. 树莓派只扫低频静态中转码。
3. 私钥不在树莓派上，签名在智能卡内完成。
4. 树莓派只负责请求解析、PIN 输入、APDU 转发和结果二维码显示。
