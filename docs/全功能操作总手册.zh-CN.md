## 0. 先认清这个项目到底有哪 4 块

当前仓库长期实际在用的是这 4 条线：

1. 树莓派离线签名器
   - 目录：`seedsigner-os/`
   - 产物：`dist/system-update-latest.img.xz`
   - 用途：扫码签名、助记词工具、智能卡工具、固件自检
2. 安卓观察钱包
   - 目录：`wallet/`
   - 产物：`dist/satochip-wallet-release.apk`
   - 用途：观察地址、准备待签名二维码、扫回公开账户或已签名交易结果、人工确认广播、给 `OKX Wallet / Bitget Wallet` 做 Web3 二维码桥接
3. 安卓“智能卡”App
   - 目录：`app/`
   - 产物：`dist/tp-qr-relay-android-latest.apk` 或按脚本现编
   - 用途：扫 `TokenPocket` 请求、直接贴卡签名、可选转成树莓派静态码
4. `Tails` 离线初始化工具备份
   - 目录：`backups/satochip-utils/`
   - 用途：离线给 `Satochip` 设 `PIN`、导入助记词、初始化卡

`BlueWallet` 不在这个仓库里，它是外部钱包。

## 1. 以后忘了先怎么判断“我该看哪部分”

如果你要：

- 刷树莓派固件
  去看树莓派离线签名器
- 做助记词、BIP85、钛板/钢板备份
  去看树莓派离线签名器
- 让树莓派给 `BlueWallet` 或自己的钱包签名
  去看树莓派离线签名器 + 安卓观察钱包
- 让 `OKX Wallet / Bitget Wallet` 通过二维码连接和签名
  连接码走树莓派 `连接钱包 -> Web3钱包`，高密度签名请求再用安卓观察钱包中转
- 给 `TokenPocket` 做智能卡签名
  去看安卓“智能卡”App
- 初始化 `Satochip` 卡
  去看 `Tails` 离线初始化工具

最容易搞错的地方只有两个：

- `wallet/` 不是热钱包，它不存私钥
- `app/` 不是资产钱包，它是 `TokenPocket` 配套签名/中转工具

## 2. 开始任何操作前，先准备这几样

最常见要准备的硬件和文件：

- 一张刷好系统的 `TF` 卡
- 树莓派设备和屏幕/按键
- 至少一张智能卡
- 智能卡 `PIN`
- 一台安卓手机
- 需要时准备 `NFC`，或者 `USB-OTG + ACR39U`

长期更稳的卡分工：

- 一张 `SeedKeeper` 专用卡
- 一张 `SatochipApplet` 专用卡

也就是：

- 一张卡只装一个程序

如果你手里的老卡已经双 applet 共存，平时查看、导入、签名通常还能继续用；但不要把这类真资金主力卡拿来做恢复出厂或频繁重刷。

## 3. 树莓派离线签名器怎么从零开始用

### 3.1 先拿当前固件入口

clean `HEAD` 基线文件是：

- `dist/system-update-latest.img.xz`
- `dist/system-update-latest.img.xz.sha256`
- `dist/system-update-latest.build-info.txt`

- 当前工作区测试包是：
- `dist/system-update-worktree-latest.img.xz`
- `dist/system-update-worktree-latest.img.xz.sha256`
- `dist/system-update-worktree-latest.build-info.txt`

当前公开 release 仍然是历史公开入口：

- `offline-signer-firmware-20260410b-clean`

如果以后不确定有没有变，先看：

- [release-manifest.json](../release-manifest.json)
- [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)

### 3.2 校验并烧录树莓派固件

在电脑里执行：

```bash
cd dist
sha256sum -c system-update-latest.img.xz.sha256
xzcat system-update-latest.img.xz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

把 `/dev/sdX` 换成真实的 `TF` 卡设备。

如果你怕写错设备，先用：

```bash
lsblk
```

看清楚再写。

### 3.3 第一次开机后会看到什么

开机后不是直接进主页，而是先看到：

- `设备登录`

第一次刷机时会强制设置：

- `4-12` 位数字登录密码

以后每次开机都先输入这个登录密码，才会进入首页。

登录通过后，首页标题是：

- `离线签名器`

首页固定 4 个入口：

- `扫码签名`
- `助记词工具`
- `智能卡工具`
- `固件自检`

### 3.4 首页 4 个入口分别是干什么的

`扫码签名`

- 扫上游钱包或手机显示的待签名二维码
- 解析交易或签名请求
- 需要时输入智能卡 `PIN`
- 先显示签名摘要，再显示签名二维码

`助记词工具`

- 创建助记词
- 导入助记词
- 核对 `BIP39` 编号
- 查看原始熵
- 做 `BIP85`
- 做二次加密/二次还原/钢板数字

`固件自检`

- 检查当前固件是否是预期版本
- 核对运行时完整性信息

`智能卡工具`

- 进入 `Satochip` 功能
- 进入 `SeedKeeper` 功能
- 进入更底层的完整菜单

## 4. 树莓派的 `扫码签名` 怎么用

### 4.1 通用签名流程

任何来源的二维码，最短流程都是：

1. 手机上游钱包显示待签名二维码
2. 树莓派进 `扫码签名`
3. 树莓派识别内容并显示摘要
4. 需要智能卡签名时输入 `PIN`
5. 树莓派先显示签名摘要
6. 确认后点 `显示签名二维码`
7. 手机上游钱包扫回结果
8. 手机上人工确认广播

### 4.2 给自己的安卓观察钱包签名

适合：

- `Arbitrum` 转账
- `WalletConnect` 请求
- `BTC PSBT`

流程：

1. 在手机钱包里准备交易
2. 手机显示待签名二维码
3. 树莓派扫码
4. 核对摘要
5. 输入卡 `PIN`
6. 树莓派先显示签名摘要
7. 确认后点 `显示签名二维码`
8. 手机扫回
9. 手机再次人工确认广播

### 4.3 给 `BlueWallet` 的 `BTC PSBT` 签名

流程：

1. 在 `BlueWallet` 观察钱包里发起 `BTC` 交易
2. `BlueWallet` 显示 `PSBT` 动态二维码
3. 树莓派进 `扫码签名`
4. 输入卡 `PIN`
5. 树莓派先显示签名摘要
6. 确认后点 `显示签名二维码`
7. `BlueWallet` 扫回
8. 再由 `BlueWallet` 广播

当前固件已经兼容的主要返回形式：

- `UR`
- `BBQR`
- 常见 `PSBT`/已签名交易回传格式

如果 `BlueWallet` 页面里因为交易太长导致广播按钮被长文本顶没，可以先复制交易，再去它的广播入口手动广播。

### 4.4 给 `TokenPocket` 做中转签名

`TokenPocket` 不是直接在树莓派里发起，而是有两条路：

1. 安卓“智能卡”App 直接扫码并贴卡签名
2. 安卓“智能卡”App 先把 `TP` 动态码转成树莓派更容易扫的静态码，再让树莓派签名

如果你用的是第 2 条：

1. 先在安卓“智能卡”App 里扫 `TP` 动态码
2. 页面上会出现树莓派静态中转二维码
3. 树莓派扫描这组静态二维码
4. 按正常签名流程完成

### 4.5 给 `OKX Wallet / Bitget Wallet` 做 Web3 桥接签名

这条线用的是安卓观察钱包 `wallet/`，不是安卓“智能卡”App `app/`。

它适合：

- Web3 钱包自己的请求二维码密度太高，树莓派直接扫不稳
- 安卓手机先扫高密度 Web3 二维码，再转成树莓派更容易扫的中转码

第一次连接账户：

1. 树莓派首页进 `连接钱包 -> Web3钱包`
2. 选择 `OKX钱包` 或 `Bitget钱包`
3. 选择 `智能卡账户` 或 `已加载助记词账户`
4. Web3 钱包添加 Keystone 硬件钱包并扫描树莓派连接码
7. 如果选智能卡，输入卡 `PIN`
8. 树莓派核对派生地址是否等于手机首页当前观察地址
9. 树莓派显示回传二维码
10. 安卓观察钱包扫回并保存公开账户信息

注意：

- 这一步手机扫回的是树莓派导出的公开账户信息
- 后面真正交易签名时，不再把签名结果扫回安卓观察钱包

连接 `OKX Wallet / Bitget Wallet`：

1. 树莓派首页进入 `连接钱包 -> Web3钱包`
2. 选择 `OKX钱包` 或 `Bitget钱包`
3. 选择 `智能卡账户` 或 `已加载助记词`
4. 树莓派显示单张静态 Keystone 连接二维码
5. `OKX Wallet / Bitget Wallet / MetaMask / Rabby / TokenPocket` 选择 Keystone 硬件钱包并扫描

签名：

1. `OKX Wallet / Bitget Wallet` 发起交易或签名
2. Web3 钱包显示签名请求二维码
3. 如果原钱包二维码太密，安卓中转 App 点 `扫描钱包二维码并中转`
4. 手机扫 Web3 钱包请求码并生成树莓派中转二维码
5. 树莓派进 `扫码签名` 扫手机中转码
6. 树莓派核对摘要并签名
7. 树莓派直接显示原钱包可扫的 `eth-signature` 结果二维码
8. `OKX Wallet / Bitget Wallet` 直接扫树莓派结果码
9. 由 Web3 钱包继续广播或完成签名

### 4.6 树莓派二维码页面按键怎么操作

自动动画二维码：

- 不用手动翻页
- 让手机持续对准即可

手动翻页二维码：

- 方向右或右侧上方键：下一张
- 方向左或右侧中间键：上一张
- 方向上：调亮
- 方向下：调暗
- 其他确认键：退出二维码页

## 5. 树莓派的 `助记词工具` 怎么用

### 5.1 创建助记词有哪些方式

当前统一入口是：

- `助记词工具 -> 创建助记词`

里面 5 个创建方式按这个顺序排列：

1. `扑克牌创建`
2. `16进制创建`
3. `骰子创建`
4. `拍照创建`
5. `智能卡创建`

导入已有助记词走：

- `助记词工具 -> 导入助记词`

怎么选：

- 想最快上手
  用 `创建助记词 -> 智能卡创建`
- 想自己掌控随机数来源
  用 `扑克牌创建 / 16进制创建 / 骰子创建`
- 手里已经有助记词
  用 `导入助记词`

### 5.2 自己离线造随机数时怎么选

`骰子创建`

- 适合最标准、最容易解释的人工熵来源
- `12/15/18/21/24` 词分别需要 `50/62/75/87/99` 次掷骰

`扑克牌创建`

- 适合已经有洗好的牌
- 输入格式是 `AH QS 9D TC` 这种牌面串
- 单副 `52` 张牌不够做 `24` 词

`16进制创建`

- 最快
- 最适合人工核对
- `12/15/18/21/24` 词分别需要 `32/40/48/56/64` 个 `HEX` 字符

如果你要看完整数量表和核验方法，继续看：

- [离线熵创建助记词教程](离线熵创建助记词教程.zh-CN.md)

### 5.3 导入助记词有哪些方式

当前可用导入方式包括：

- 普通 `12 / 15 / 18 / 21 / 24` 词导入
- `按编号导入 BIP39 助记词`
- 扫描 `SeedQR`
- 从 `SeedKeeper` 导入

如果你拿到的是纯数字编号备份，优先用：

- `按编号导入 BIP39 助记词`

### 5.4 `BIP39 单词自检` 什么时候用

它适合两种情况：

- 你手里只有词，想反查它的编号
- 你手里只有编号，想反查标准英文单词

也就是：

- `输入单词查编号`
- `输入编号查单词`

### 5.5 `已加载助记词` 里最常用的功能有哪些

助记词一旦加载完成，绝大多数后续操作都从这里继续。

最常用功能：

- `查看 BIP39 序号`
- `查看原始熵`
- `派生路径算地址`
- `导出当前助记词 BTC zpub`
- `导出当前助记词 BTC xpub`
- `BIP-85 子助记词`
- `写入当前助记词到智能卡`
- `写入当前助记词到 SeedKeeper`
- `二次加密助记词`
- `二次还原助记词`
- `转成钢板打孔数字`
- `删除助记词`

当前最标准的核对页是：

- `查看 BIP39 序号`

以后不要再按旧习惯只找“查看助记词”。

### 5.6 `查看原始熵` 怎么用

如果当前助记词是标准英文 `BIP39` 助记词，就可以看到：

- `查看原始熵`

这串 `HEX` 适合做两件事：

- 显示二维码，让手机再扫一份留档
- 放进支持 `BIP39 entropy` 的工具里做独立复核

它不是：

- 骰子原始串
- 你自己发明的编号串

### 5.7 `BIP85` 子助记词怎么用

路径：

- `已加载助记词 -> BIP-85 子助记词`

当前可做的事：

- 选择 `12 / 18 / 24` 词
- 输入 `BIP85 index`
- 查看子助记词
- 查看子助记词 `BIP39` 编号
- `验证备份`
- `导入到树莓派`
- `子助记词写入智能卡`
- `子助记词写入 SeedKeeper`

适合：

- 一条主助记词派生很多独立钱包
- 给不同用途单独分子钱包

### 5.8 二次加密 / 二次还原 / 钢板数字怎么理解

这条线不是标准 `BIP39` 直备份。

它的真实用途是：

1. 先把真助记词转成假的中间助记词
2. 再把假的中间助记词保存或转成钢板数字
3. 恢复时先恢复出假的助记词
4. 再做二次还原回到真助记词

标准流程：

1. 加载真助记词
2. 进入 `二次加密助记词`
3. 给每个词输入规则和数字
4. 得到假的助记词
5. 继续：
   - `查看 BIP39 序号`
   - `保存二次加密助记词到 SeedKeeper`
   - `转成钢板打孔数字`
6. 恢复时先：
   - `从钢板数字恢复二次助记词`
7. 最后再：
   - `二次还原助记词`

要记住：

- 从钢板恢复出来的先是假助记词
- 做完 `二次还原助记词` 才回到真助记词

## 6. 树莓派的 `智能卡工具` 怎么用

### 6.1 顶层入口怎么理解

顶层只保留 3 个入口：

- `Satochip 功能`
- `SeedKeeper 功能`
- `完整智能卡菜单`

日常优先用前两个。

### 6.2 `Satochip 功能` 适合做什么

偏向签名卡，常用的是：

- `按路径查看 Satochip 地址`
- `导出 Satochip BTC zpub`
- `导出 Satochip BTC xpub`
- `写入已加载助记词到 Satochip`
- `更改 Satochip PIN`
- `重置 Satochip`

适合：

- 把当前助记词写进签名卡
- 查看卡里派生的地址
- 导出扩展公钥给观察钱包

### 6.3 `SeedKeeper 功能` 适合做什么

偏向助记词和备份管理，常用的是：

- `智能卡创建`
- `写入已加载助记词到 SeedKeeper`
- `保存二次加密助记词到 SeedKeeper`
- `从 SeedKeeper 加载二次加密助记词`
- `更改 SeedKeeper PIN`
- `重置 SeedKeeper`
- `更多 SeedKeeper 功能`

适合：

- 把假助记词或备份数据保存在卡里
- 把卡作为助记词/备份库来用

### 6.4 `完整智能卡菜单` 什么时候进

只有这些情况才建议进：

- 想看更底层卡信息
- 想看描述符、容量、更多杂项
- 你明确知道自己在做什么

日常普通用户不建议从这里开始。

## 7. 树莓派的 `固件自检` 怎么用

路径：

- 首页 -> `固件自检`

适合：

- 刷机后确认当前固件是不是你预期的版本
- 做发布前检查
- 以后时间久了再复核当前机器是不是那张正式镜像

如果你是维护者，还要搭配：

- [固件与源码对应关系](固件与源码对应关系.zh-CN.md)
- [版本时间线与发布入口](版本时间线与发布入口.zh-CN.md)

## 8. 安卓观察钱包怎么完整使用

### 8.1 这不是热钱包

手机里不存私钥。

它负责：

- 保存观察地址
- 生成待树莓派签名的二维码
- 扫回树莓派返回结果
- 人工确认广播
- 协调高安全 `WalletConnect`
- 桥接 `OKX Wallet / Bitget Wallet` 的 Web3 二维码签名流程

### 8.2 第一次安装后先过哪几个门槛

高安全模式下，下面任一项不满足都可能被拦下：

- 已设置强生物识别
- 没开 `USB 调试`
- 没开开发者选项
- 没有 `Root / Magisk / Hook`
- 系统不是 `test-keys`

被拦住时，页面会直接提示原因。

### 8.3 顶部 3 个标签页分别做什么

- `首页`
- `活动`
- `DApp`

`首页`

- 观察地址
- 资产
- 转账
- `BTC` 账户

`活动`

- 最近链上活动

`DApp`

- `WalletConnect` 高安全协调器
- `OKX Wallet / Bitget Wallet` Web3 二维码桥接

### 8.4 `首页 -> Arbitrum` 模式怎么用

能做的事：

- 填 `派生路径`
- 连接树莓派
- 手动添加观察地址
- 选择当前地址
- 查看资产和最近活动
- 发起 `EVM` 转账待签名请求

最短流程：

1. 选择或添加观察地址
2. 输入转账信息
3. 生成待签名二维码
4. 让树莓派签名
5. 手机扫回
6. 手机人工确认广播

### 8.5 `首页 -> BTC` 模式怎么用

能做的事：

- 扫码导入 `xpub / ypub / zpub`
- 粘贴导入 `xpub / ypub / zpub`
- 查看已导入账户
- 同步余额、活动、下一收款地址
- 准备 `BTC PSBT`

最短流程：

1. 从树莓派或卡里导出 `xpub / ypub / zpub`
2. 手机导入观察账户
3. 等同步余额和活动
4. 准备交易
5. 手机显示 `PSBT` 待签名二维码
6. 树莓派扫码签名
7. 手机扫回已签名交易
8. 人工确认广播

当前主网同步优先走：

- `Electrum`

如果 `Electrum` 暂时不可用，才会自动回退旧同步方式。

### 8.6 `DApp` 页怎么用

它不是浏览器，而是高安全协调器。

支持：

- 扫码导入 `WalletConnect v2`
- 从相册导入二维码
- 手动粘贴 `WalletConnect` 或原始请求
- 把首页当前观察地址绑定到树莓派导出的公开 Web3 账户
- 显示 `OKX Wallet / Bitget Wallet` 可扫的连接二维码
- 扫描 Web3 钱包发出的签名请求二维码
- 显示 Web3 钱包可扫回的签名结果二维码

Web3 桥接最短流程：

1. 树莓派首页进 `连接钱包 -> Web3钱包`
2. 选择 `OKX钱包` 或 `Bitget钱包`
3. 选择 `智能卡账户` 或 `已加载助记词`
4. Web3 钱包添加 Keystone 硬件钱包并扫描树莓派连接码
5. Web3 钱包发起签名时，安卓观察钱包点 `扫描钱包二维码并中转`
6. 安卓观察钱包把高密度请求码转成树莓派中转码
7. 树莓派签名后，直接显示原钱包可扫的结果码
8. `OKX Wallet / Bitget Wallet` 直接扫树莓派结果码

当前策略：

- 只接受已验证、`HTTPS`、主机合法的 DApp
- 信任范围绑定到 `主机 + 链 + 地址`
- 超过 `24` 小时会失效
- 锁屏或退后台会主动清理会话

### 8.7 安卓观察钱包最常见的 4 个误解

- 它不是热钱包
- 它不是内置浏览器钱包
- 它不是自动广播器，广播前会让你再确认一次
- 锁屏后 `DApp` 断开通常是高安全设计，不是故障

## 9. 安卓“智能卡”App 怎么完整使用

### 9.1 它是干什么的

它负责：

- 扫 `TokenPocket` 请求
- 显示请求摘要
- 输入 `PIN`
- 通过 `NFC` 或 `USB-OTG + ACR39U` 贴卡签名
- 显示回扫给 `TP` 的结果二维码
- 额外生成给树莓派扫描的静态中转二维码

它不是：

- 独立钱包
- 助记词管理器

### 9.2 使用前准备什么

至少准备：

- 一张已经初始化好的智能卡
- 卡的 `PIN`
- 支持 `NFC` 的手机，或者 `USB-OTG + ACR39U`
- `TokenPocket`

### 9.3 主界面关键区域怎么理解

常见区域：

- `BIP32 路径`
- `卡 PIN`
- `解锁`
- `TP 请求字符串`
- `扫码`
- `解析`
- `贴卡/插卡签名`

解锁成功后通常还会显示：

- 当前钱包地址

解析成功后通常还会显示：

- 请求摘要
- 转账/合约信息
- `DApp` 信息
- 树莓派静态中转二维码
- 回扫二维码

### 9.4 最常用流程：手机直接贴卡签名

1. 在 `TokenPocket` 发起签名或交易
2. 打开安卓“智能卡”App
3. 点 `扫码`
4. 扫 `TP` 请求二维码
5. 输入 `PIN`
6. 点 `解锁`
7. 核对请求摘要、转账/合约信息、`DApp` 信息
8. 点 `已核对，允许签名`
9. 点 `贴卡/插卡签名`
10. 用 `NFC` 贴卡，或者插上 `USB-OTG + ACR39U`
11. 成功后让 `TP` 扫回结果二维码

### 9.5 另一条流程：把 `TP` 动态码转成树莓派静态码

1. 扫 `TP` 动态码
2. App 解析后生成 `树莓派静态中转二维码`
3. 如果有多张，会自动轮播，也可手动切换
4. 让树莓派扫描这组静态码
5. 树莓派按正常流程签名

适合：

- `TP` 动态码太快
- 树莓派直接扫不稳

### 9.6 这条链路最常见的问题

贴卡没反应：

- 先确认手机 `NFC` 已开启
- 卡位置对准
- 没有别的 App 抢占 `NFC`

`USB` 读卡器没反应：

- 先确认 `OTG` 正常
- `ACR39U` 已通电
- 已允许 App 访问 `USB`

提示 `TypedDataLegacy` 不支持：

- 让 `TP` 或 `DApp` 优先改用 `signTypedData` 或 `signTypeDataV4`
  这里保留的是 `TP` 当前链路里的历史拼写。

## 11. 四条最常见完整链路

### 11.1 给自己的安卓观察钱包做冷签

1. 手机钱包准备交易
2. 手机显示待签名二维码
3. 树莓派 `扫码签名`
4. 输入智能卡 `PIN`
5. 树莓派先显示签名摘要
6. 确认后点 `显示签名二维码`
7. 手机扫回
8. 手机人工确认广播

### 11.2 给 `BlueWallet` 做 `BTC PSBT` 冷签

1. `BlueWallet` 发起交易
2. `BlueWallet` 显示 `PSBT`
3. 树莓派 `扫码签名`
4. 输入 `PIN`
5. 树莓派先显示签名摘要
6. 确认后点 `显示签名二维码`
7. `BlueWallet` 扫回
8. `BlueWallet` 广播

### 11.3 给 `TokenPocket` 做签名

1. `TP` 发起请求
2. 安卓“智能卡”App 扫码
3. 直接贴卡签名，或者先转成树莓派静态码

4. 安卓观察钱包扫 Web3 钱包请求码
5. 安卓观察钱包显示树莓派中转码
6. 树莓派扫码、核对、签名
7. 树莓派直接显示原钱包可扫的结果码
8. Web3 钱包直接扫树莓派结果码
9. Web3 钱包扫回安卓观察钱包显示的结果码

## 12. 最常忘的 13 件事

1. 树莓派开机先看到的是 `设备登录`，不是主页。
2. 树莓派首页只有 4 个入口。
3. 当前标准核对页是 `查看 BIP39 序号`。
4. `BIP85` 子助记词和二次加密后的假助记词不是一回事。
5. 钢板数字路线和标准钛板直备份不是一回事。
6. `SeedKeeper` 和 `SatochipApplet` 不是同一个 applet。
7. 长期最稳方案是一张卡只装一个程序。
8. `wallet/` 不是热钱包。
9. `app/` 不是资产钱包。
10. `BlueWallet` 不在本仓库里。
11. `OKX Wallet / Bitget Wallet` 走 `wallet/` 的 Web3 桥接，不走 `app/`。
12. `wallet/` 生成的是待签名请求，不是手机本地直接签。
13. 以后让 AI 接手时，先让它看 `release-manifest.json`，不要让它自己猜 tag 和命令。
