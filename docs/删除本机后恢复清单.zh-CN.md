# 删除本机后恢复清单

这页只回答一个问题：

- 如果以后这台电脑的项目文件夹删了，怎样从 `GitHub` 和你自己离线保留的材料里，把现在这套项目恢复回来并继续编译？

先说最短结论：

- 固件这条线，源码和方法基本已经都在 `GitHub`
- 钱包 `wallet/` 这条线，源码和方法也在 `GitHub`
- 但想继续做出和现在正式发布版一致、还能覆盖旧安装包的 `APK`，必须保住原来的正式签名 `keystore`

## 1. 哪些东西已经在 GitHub

现在仓库里已经有：

- 源代码
- 构建脚本
- 主要维护文档
- 发布入口和校验说明
- 已上传的固件 / 钱包发布资产

所以如果只是本地项目目录没了，先重新拉仓库：

```bash
git clone https://github.com/akg5188/satochip-signer.git
cd satochip-signer
```

然后再按文档恢复构建环境。

## 2. 哪些东西不在 GitHub，但你必须自己保住

这些是最关键的离线材料：

- 钱包正式签名 `keystore` 文件
- `wallet/keystore.properties`
- `storePassword`
- `keyAlias`
- `keyPassword`

如果你还想继续维护 `app/` 的正式签名，也应该保住：

- `app/keystore.properties`
- `app/` 对应的正式签名 `keystore`
- 对应密码和别名

如果这些东西丢了：

- 固件一般还能继续重建
- 钱包还能编出测试包
- 但不一定还能做出和当前正式版同签名、可直接覆盖安装的正式 `APK`

## 3. 新机器最短恢复顺序

建议按这个顺序走，不容易绕乱：

1. 从 `GitHub` 重新拉源码仓库
2. 安装 `JDK`、`Android SDK`、`platform-tools`
3. 按仓库文档恢复 `local.properties`
4. 恢复 `wallet/keystore.properties` 和正式 `keystore`
5. 如果要维护 `app/` 正式签名，再恢复 `app/keystore.properties`
6. 先跑钱包测试构建确认环境没坏
7. 再跑正式钱包构建
8. 再跑固件构建和校验

## 4. 恢复后先做什么验证

恢复完不要直接发版，先做这几步：

1. 看 `git status`，确认仓库干净
2. 先编钱包测试包，确认 `Gradle / SDK` 正常
3. 再编正式钱包，确认签名材料可用
4. 运行发布校验脚本，确认 `sha256` 和 `build-info` 自洽
5. 再决定要不要更新 `dist/` 和 `GitHub Releases`

## 5. 你现在最该单独备份什么

最少单独离线保留这几样：

- 钱包正式 `keystore`
- `wallet/keystore.properties`
- `app/keystore.properties`
- `app/` 的正式 `keystore`
- 所有 `keystore` 对应密码
- 你自己确认可用的构建环境版本记录

最稳的做法是：

- 一份放加密 `U` 盘
- 一份放离线移动硬盘
- 密码提示单独保管，不和 `keystore` 放在一起

## 6. 删机后还能恢复到什么程度

### 树莓派固件

- 基本可以从 `GitHub` 恢复源码和构建方法
- 通常可以继续重建
- 是否字节完全一样，还会受构建环境影响

### 安卓观察钱包 `wallet/`

- 可以从 `GitHub` 恢复源码和构建方法
- 可以继续编测试包
- 想做出和当前正式版一致的发布包，必须保住原来的正式 `keystore`

### 安卓“智能卡”App `app/`

- 没有正式签名材料也还能编测试包
- 想继续沿用同一个正式签名，也要保住它自己的 `keystore`
